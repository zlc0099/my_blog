# 活文档协议 (Living Documents)

本协议贯穿 P2-P7，规定任务过程文档（`CHECKLIST.md` / `DESIGN.md` / `HANDOVER.md`）的**实时更新纪律**。

核心原则：**清单是任务状态的唯一事实源（Single Source of Truth）。** 任何只存在于对话里、没有落盘的进度 / 决策 / 假设，都视为"不存在"——对话会丢，文件不会。

## 一、更新节奏分级

不是所有更新都要"立即"，按事件性质分三档：

| 档位 | 触发事件 | 时限 |
|------|----------|------|
| **立即** | 新假设、新决策（含理由）、新风险、新发现事项、验证证据产出、回滚点打点、根因证实/证伪 | **事件发生即写入**，不许"等会儿一起写" |
| **批末** | 任务状态流转（`[ ]`→`[~]`→`[x]`/`[!]`）、HANDOVER.md 刷新 | 每批（1-3 个任务）结束时 |
| **阶段末** | DESIGN.md 修订、清单阶段性整理、评审结论写入 | 每个阶段（P2/P5/P6）结束时 |

判断口诀：**"丢了会疼的立即写，只是推进的批末写，成体系的阶段末写。"**

## 二、事件驱动更新清单（立即档详解）

执行过程中发生以下任一事件，**当步就写**：

1. **做了新假设** → 假设登记加一行（假设内容 / 依据 / 若错的影响）。
2. **做了新决策** → 决策日志加一行（决策 / 备选 / 理由）。"为什么这么选"当场记，事后补的决策日志一定失真。
3. **发现新风险或范围外问题** → 风险登记或"发现事项"节。
4. **拿到验证输出** → 验证证据节，原样贴关键部分。
5. **打了回滚点** → 回滚点表。
6. **调试线中假设被证实/证伪** → 假设登记标注结论。

## 三、中途交接 (Living Handover)

**`HANDOVER.md` 不再是 P7 专属产物。** 从 P4 第一批开始，每批结束时顺手刷新它的"当前进度"与"下一步"两节（其余节仅在变化时更新）。

效果：**任意时刻对话中断（崩溃 / 上下文爆掉 / 用户关闭窗口），下一个对话都能从 HANDOVER 恢复到最近一批的断点**，而不是从头考古。P7 时只做最终终态化，不再从零写。

精简档可降级：仅维护 CHECKLIST 状态流转，不强制中途刷新 HANDOVER。

## 四、设计文档同步规则

执行中出现设计层面的修订（评审打回、架构复盘改方案、验证暴露设计缺陷）时：

1. **先改 `DESIGN.md`，再改代码** —— 设计文档与代码实现不允许长期不一致。
2. 修订本身记入决策日志（D 条目：修订了什么 / 为什么）。
3. 若修订影响任务列表，同步更新 CHECKLIST 的任务与 DoD。
4. 修订影响范围超出本次任务时，走范围守卫：先问用户。

## 五、批末自检（30 秒）

每批结束时快速过一遍：

- [ ] 清单状态与实际代码状态一致？（改了的都标了 `[x]`，没改的没误标）
- [ ] 本批产生的新假设/决策/风险都已落盘？
- [ ] HANDOVER 的"进度/下一步"反映了最新状态？
- [ ] 有无未解释的偏差（计划改 A 实际动了 B）？

发现不一致**当场修正**，不带病进下一批。

## 六、非正常中断的恢复

上一对话非正常中断（没有走 P7）时，P0 续接按 `handover-protocol.md` 第五节执行，额外注意：

1. HANDOVER 停在批末状态是正常的——以 `git status` / `git diff` 核对代码实际进度，**以代码为准**。
2. 清单中最后一个 `[~]`（进行中）的任务，先确认其实际完成度再决定续做或重做。
3. 恢复后立即把核对结论写进清单（这本身就是一次活文档更新）。
