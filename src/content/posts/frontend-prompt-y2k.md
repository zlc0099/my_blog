这套提示词把 1998—2006 年前后的个人主页、Flash 站点、网络音乐社区、数码产品官网和早期论坛的视觉语言，整理成可用于现代前端的 UI 规则。

它重点统一材质、配色、字阶、控件、装饰密度和交互反馈；导航项、栏目数量、页面结构和业务内容由项目实际需要决定。复古感来自 Chrome 金属、Aqua 亮面、像素图形和网页徽章的组合，而不是全屏霓虹或游戏化界面。

## 适合什么场景

- 希望呈现早期互联网个性、怀旧数码文化和千禧未来主义的站点。
- 个人主页、作品集、数字杂志、活动专题、音乐/游戏社区。
- 需要比常规现代网站更有材质和装饰表达，但仍要求响应式、键盘操作和真实业务能力的项目。

不适合直接套用在高密度生产后台、审批系统或需要极度克制阅读的正文场景；如果必须使用，应降低装饰密度，把 Y2K 元素集中在页头、标签、徽章和局部强调上。

## 视觉构成

- **Chrome 金属**：银白高光、明暗过渡和细腻描边，用于品牌、标题装饰和少量重点控件。
- **Aqua 亮面**：顶部高光、底部暗部和短促按压反馈，用于主要按钮。
- **电子蓝与青色**：主交互、链接和数码状态；粉紫色只做贴纸与局部渐变。
- **像素与网点**：小尺寸像素图案、棋盘格、点阵和轻噪点，作为低对比背景或徽章纹理。
- **网页结构**：导航、内容分区、辅助信息栏、页脚、徽章和状态条应保留真实网页感。
- **装饰克制**：星星、闪光、贴纸和像素图标只能集中在少数区域，不能遮挡正文与操作。

## 使用边界

- 不把每个组件都做成玻璃卡片，也不把整站强制压成黑底霓虹。
- 正文使用易读的现代无衬线字体；像素字体只用于短标签和装饰。
- 不虚构访问量、在线人数、认证信息或技术能力。
- 所有按钮、链接、菜单、筛选器和表单必须连接真实行为；保留现有业务逻辑、数据绑定和校验。
- 装饰不能影响阅读、键盘焦点、移动端点击区域和页面性能。

## 完整提示词

````prompt
# 前端 UI 提示词：千禧年代网页风格（Y2K Retro Web）

## 一、设计目标

你是一名资深前端设计师，擅长 Y2K 千禧美学、早期互联网视觉文化、复古网页设计与现代 Web 交互。

请在当前项目中建立一套完整、统一、可落地的「千禧年代网页风格」UI 设计系统。

整体参考 1998—2006 年前后的网站视觉语言，融合早期个人主页、Flash 网站、网络音乐社区、复古科技产品官网、互联网论坛和数字文化杂志的设计特征。

目标不是制作一个普通现代网站后添加几个复古装饰，而是让整个项目具有明确的早期互联网气质，同时满足现代浏览器、响应式布局、键盘操作与真实业务功能的要求。

### 核心视觉关键词

- Y2K 千禧美学
- Retro Internet / Old Web
- Chrome Metallic / 银色金属质感
- Aqua Glossy UI / 亮面界面
- Pixel Art / 像素图形
- Cyber Blue / 电子蓝
- Digital Stickers / 网页贴纸
- Web Badges / 复古徽章
- Star Sparkles / 星星闪光
- Early Personal Websites / 早期个人主页
- Internet Nostalgia / 互联网怀旧
- Futuristic Optimism / 千禧年代的未来主义

### 设计原则

1. **复古但不混乱：** 可以使用密集排版与装饰元素，但必须有清晰的信息层级。
2. **数字感而非纯赛博朋克：** 优先表现早期互联网对未来科技的乐观想象，不要变成全屏黑底霓虹。
3. **材质丰富：** 使用金属渐变、透明塑料、亮面按钮、细腻描边与像素装饰。
4. **网站感优先：** 保留导航栏、页脚、内容分区、链接、徽章和状态栏等真实网页结构。
5. **装饰服务内容：** 星星、贴纸、像素图标等元素需要有节制，不能遮挡正文。
6. **结构保持灵活：** 不预设页面数量、栏目数量、卡片数量或固定模块结构，由项目实际内容决定。

---

## 二、整体视觉方向

### 2.1 主要风格

采用「早期个人网站 + 千禧未来主义 + 复古数码产品界面」的混合风格。

可以从以下视觉元素中选择合适的组合：

- 银色金属渐变和铬合金质感。
- 蓝紫色、青色和粉色的高光渐变。
- 半透明塑料面板和亮面按钮。
- 像素星星、光标、箭头、笑脸和装饰图标。
- 早期网页风格的细线分隔符与小型标题栏。
- 复古网页徽章、访客计数器风格的装饰组件。
- 轻微的噪点、网点、扫描纹理或棋盘格图案。
- 带有数码产品质感的边框、标签和状态指示灯。
- 具有早期互联网气息的滚动字幕或状态提示，但仅在确有需要时使用。

### 2.2 风格边界

避免以下错误方向：

- 直接套用现代 SaaS 后台布局，再随意加上霓虹色。
- 所有内容都使用像素字体，导致正文难以阅读。
- 将每个组件都制作成玻璃卡片。
- 全屏黑底、绿色代码雨和高强度荧光描边。
- 过度使用故障艺术、RGB 分离和闪烁动画。
- 大量使用与内容无关的装饰图案。
- 将网站做成游戏启动器或科幻操作系统，失去真实网页的信息架构。

## 三、设计 Token 与配色规范

请建立统一的 CSS 变量体系。所有页面与组件应优先使用共享 Token，避免颜色和材质随意变化。

以下为推荐的初始配色：

```css
:root {
  /* 千禧年代主色 */
  --y2k-blue: #58A9F8;
  --y2k-cyan: #71E3F0;
  --y2k-purple: #A78BFA;
  --y2k-pink: #FF9ED8;

  /* 金属与中性色 */
  --y2k-chrome-light: #FFFFFF;
  --y2k-chrome-mid: #DCE3EB;
  --y2k-chrome-dark: #8998AA;
  --y2k-ink: #20273A;
  --y2k-muted: #68758A;

  /* 页面背景 */
  --y2k-bg: #EAF2FF;
  --y2k-panel: rgba(255, 255, 255, 0.88);
  --y2k-panel-border: #A9BEDA;

  /* 交互状态 */
  --y2k-primary: #367FEA;
  --y2k-primary-hover: #2466CC;
  --y2k-focus: #F3A5FF;
  --y2k-success: #3D9D80;
  --y2k-warning: #D79743;
  --y2k-danger: #D95D78;

  /* 形状与层次 */
  --y2k-radius-sm: 4px;
  --y2k-radius-md: 10px;
  --y2k-radius-lg: 16px;

  --y2k-border: 1px solid var(--y2k-panel-border);
  --y2k-shadow:
    0 3px 0 rgba(73, 105, 150, 0.12),
    0 8px 22px rgba(60, 90, 140, 0.12);

  --y2k-transition: 180ms ease;
}
```

### 配色使用规则

- 电子蓝作为主要交互色与视觉识别色。
- 银白色用于金属表面、按钮高光和装饰边框。
- 青色用于数码感、链接强调与小面积光效。
- 粉紫色用于贴纸、特殊标签和局部渐变。
- 深蓝灰用于正文和高对比文字。
- 大面积背景优先采用浅蓝、淡紫、银白或低对比渐变。
- 深色主题可以使用深蓝黑背景与银色界面，但不要将所有页面强制设为黑底。
- 强调色应有明确用途，不允许每个组件随意挑选不同颜色。

如果现有项目已有品牌色，应优先协调使用，不要为了复古风格彻底破坏原有品牌识别。

## 四、材质系统

千禧年代网页风格的关键不是单纯的配色，而是不同材质之间的组合。

### 4.1 Chrome 金属质感

用于主要标题装饰、品牌标识、特殊按钮和局部强调。

```css
.y2k-chrome {
  background: linear-gradient(
    180deg,
    #FFFFFF 0%,
    #DCE3EB 20%,
    #FFFFFF 36%,
    #A8B6C7 52%,
    #F5F7FA 68%,
    #A0AFC0 100%
  );

  border: 1px solid #A3B2C5;
  color: #26364B;
  text-shadow: 0 1px 0 rgba(255, 255, 255, 0.9);
}
```

使用规则：

- 金属渐变应具有清晰的高光与明暗过渡。
- 不要给所有普通按钮添加金属效果。
- 避免过于写实的重金属纹理。
- 正文不得直接使用低对比度的金属渐变文字。
- 复杂渐变优先用于装饰性元素，而非大段文字。

### 4.2 Aqua 亮面按钮

```css
.y2k-aqua-button {
  background: linear-gradient(
    180deg,
    #C5F8FF 0%,
    #75D7FA 45%,
    #438FF0 100%
  );

  border: 1px solid #4D91D8;
  border-radius: var(--y2k-radius-md);
  box-shadow:
    inset 0 1px 0 rgba(255, 255, 255, 0.95),
    inset 0 -2px 0 rgba(36, 91, 160, 0.18),
    0 2px 0 rgba(50, 83, 133, 0.14);
}
```

按钮应具有明显的顶部高光与底部暗部，呈现早期数码产品的塑料亮面质感。

### 4.3 复古面板

面板可以采用轻微渐变背景、细边框和浅阴影。

允许存在少量直角或较小圆角，以表现早期网页的硬朗结构；同时可以在特定主视觉区域使用较大的圆角。

不要将所有区域统一为现代设计系统中常见的大圆角卡片。

### 4.4 像素纹理

可在徽章、标签、装饰背景和局部图案中使用：

- 8-bit 像素图案。
- 棋盘格。
- 小尺寸点阵。
- 网点阴影。
- 简单的重复几何纹理。

纹理必须低于正文的视觉优先级，不能干扰阅读。

## 五、字体与排版体系

### 5.1 字体组合

使用「现代易读字体 + 少量复古字体」的组合。

```css
:root {
  --font-y2k-display:
    "Arial Black",
    "Arial",
    sans-serif;

  --font-y2k-pixel:
    "Press Start 2P",
    "Courier New",
    monospace;

  --font-y2k-body:
    "Inter",
    "PingFang SC",
    "Microsoft YaHei",
    sans-serif;

  --font-y2k-mono:
    "JetBrains Mono",
    "Consolas",
    monospace;
}
```

字体使用规则：

- 主标题：粗体无衬线字体，可配合大写英文、字距和金属装饰。
- 正文：清晰的现代无衬线字体，保证长时间阅读的舒适度。
- 小型标签：可使用等宽字体，营造早期计算机界面感。
- 像素字体：只用于短标签、徽章、装饰文字和少量标题。
- 中文正文不要强制使用像素字体。
- 字体资源无法加载时，必须存在合理的本地字体回退方案。

### 5.2 字阶体系

| 层级 | 建议字号 | 用途 |
|---|---:|---|
| Display | 40–64px | 首页视觉标题 |
| H1 | 32–44px | 页面主标题 |
| H2 | 24–32px | 内容分区 |
| H3 | 18–24px | 子标题 |
| Body | 14–17px | 正文与描述 |
| Label | 11–13px | 标签、徽章、状态 |
| Pixel Label | 8–12px | 少量像素风装饰 |

所有字号需要根据实际屏幕宽度适当调整。

### 5.3 排版风格

- 可以使用大写英文、短横线、数字编号与小型标签。
- 标题可以搭配轻微文字阴影或描边。
- 正文必须保持足够的行高与合理的行宽。
- 信息密集区域可使用更紧凑的排版，但需要清晰的分区。
- 避免所有文字都居中。
- 避免所有标题都使用相同的装饰效果。
- 不得为了复古效果破坏中文标点、换行和可读性。

## 六、网页结构与布局规范

### 6.1 整体布局

整体应体现早期互联网网页的结构感，而不是机械地采用现代全屏大留白布局。

可以根据真实内容组合：

- 顶部品牌区域。
- 主导航。
- 次级导航或标签条。
- 主内容区。
- 辅助信息栏。
- 贴纸与网页徽章。
- 状态信息与页脚。
- 文章、项目、作品或其他业务内容。

这些只是可选的布局元素，不是每个页面都必须具备的固定模块。

### 6.2 布局特征

- 可采用带有边框的内容容器。
- 可在标题区域使用细线、渐变条和小型图标。
- 允许内容区具有适度的密集感。
- 通过间距、背景色和分隔线明确内容层次。
- 允许在主内容旁设置辅助区域，但不能挤压主要内容。
- 允许局部不对称构图，避免所有页面都像标准化后台模板。
- 桌面端可以使用多列布局，移动端应自然转换为单列或更适合小屏的结构。

### 6.3 不固定栏目数量

不要擅自决定网站必须包含多少个导航项、栏目、卡片、徽章或内容模块。

应根据当前项目真实的业务结构和内容组织方式决定布局。

不允许为了表现复古风格而虚构大量空栏目、空卡片、无意义的计数器或重复装饰区域。

## 七、导航栏与链接

### 7.1 导航栏

导航栏应具有明显的早期网页气质。

可采用：

- 银色渐变导航背景。
- 蓝色或青色的活动标签。
- 细边框分隔。
- 具有层次感的按钮。
- 小型像素图标。
- 轻量的状态标记。

不要把导航栏设计成复杂的游戏 HUD。

### 7.2 链接状态

所有链接应明确区分：

- 默认状态。
- 悬停状态。
- 键盘聚焦状态。
- 已访问状态（在语义合适时）。
- 当前页面状态。

悬停时可以出现下划线、颜色变化或轻微亮面效果，但不能仅依赖颜色变化来表明交互。

链接必须指向真实页面或有效锚点。不能让视觉上可点击的文本成为无效链接。

---

## 八、复古按钮与表单

### 8.1 按钮风格

按钮应体现早期操作系统、数码产品与复古网页控件的质感。

允许使用：

- 顶部高光。
- 底部暗部。
- 细边框。
- 轻微立体阴影。
- 短促的按压动画。
- 小型图标与文字组合。

按钮层级应根据实际操作重要性划分，不要所有按钮都使用高饱和度亮面效果。

### 8.2 交互状态

| 状态 | 设计要求 |
|---|---|
| Default | 保留基础材质与明确文字 |
| Hover | 提亮高光、调整边框或颜色 |
| Focus | 显示清晰的键盘焦点轮廓 |
| Active | 轻微下压，体现实体按钮反馈 |
| Selected | 持续显示选中状态 |
| Disabled | 降低对比度，阻止操作 |
| Loading | 显示等待反馈，避免重复提交 |
| Success | 使用清晰的成功提示 |
| Error | 显示错误原因或恢复建议 |

### 8.3 表单控件

输入框、下拉框、复选框和单选框可以使用复古边框、细腻渐变和小型状态标识，但必须保证现代浏览器下的正确行为。

不要仅通过装饰改变控件外观，却破坏原有表单验证、键盘操作或可访问性。

---

## 九、徽章、贴纸与装饰组件

这是 Y2K 风格的重要识别元素，但必须克制使用。

### 9.1 Web Badge

可以设计类似早期个人网站的徽章：

- 小尺寸横向徽章。
- 像素边框。
- 金属渐变底。
- 蓝紫色渐变文字。
- 小型星星或图标。
- 短文本标识。

徽章可以用于展示真实的技术栈、项目状态、文章分类或网站信息。

不要虚构认证、统计数据或技术能力。

### 9.2 Digital Sticker

可以使用：

- 星星。
- 小型笑脸。
- 像素爱心。
- 复古光标。
- 闪光符号。
- 千禧年代数码图形。
- 简单的几何贴纸。

贴纸应放置在标题附近、装饰区域或内容容器边缘。

必须避免遮挡按钮、正文、表单和移动端主要操作。

### 9.3 装饰密度

装饰元素应有主次。

建议只在部分区域形成高密度装饰，其他区域保持相对干净，以建立视觉节奏。

不要在每个标题、每个按钮、每张卡片和每个角落重复放置相同的星星或闪光图案。

## 十、背景与图形效果

### 10.1 推荐背景

可以结合以下元素：

- 浅蓝到银白的渐变。
- 蓝紫色光晕。
- 微弱的网格。
- 小型棋盘格纹理。
- 低对比度的点阵。
- 数码噪点。
- 少量星星或几何图案。

背景应支持主要内容，而不是抢夺视觉焦点。

### 10.2 图形效果

可以使用 CSS 渐变、伪元素、SVG 或项目已有图片资源实现装饰。

避免为了少量装饰引入过重的图形依赖。

背景纹理应尽可能轻量，确保页面在不同分辨率下不会出现明显拉伸、重复错位或性能问题。

### 10.3 动画限制

- 悬停动画应短促。
- 光泽扫过效果仅用于少数重点元素。
- 闪烁动画必须克制。
- 不允许高频闪烁或大面积快速色彩变化。
- 装饰动画不得影响阅读与交互。
- 支持 `prefers-reduced-motion`，减少非必要动效。

## 十一、状态栏与复古网页元素

根据项目需要，可以设计以下辅助元素：

- 简洁的在线状态标记。
- 当前时间或更新时间。
- 真实的访问统计。
- 页面加载提示。
- 小型系统状态条。
- 章节或内容分类标签。
- 具有复古数码质感的提示条。

这些元素不是必选模块。

如果展示访问量、在线人数、更新时间或其他统计信息，必须使用真实数据或明确标记的演示数据。不能把虚构的访问计数伪装成真实网站统计。

不要为了复古感强行添加浏览器窗口仿制品、无意义的进度条或装饰性系统报错。

---

## 十二、交互与动效规范

### 12.1 动效原则

- 交互需要即时反馈。
- 动效时间保持简短。
- 不要所有元素同时动画。
- 动效应与材质相匹配。
- 复古视觉不等于低效、卡顿或难以操作。

### 12.2 推荐反馈

- 按钮按下时轻微下沉。
- 标签切换时改变背景和边框。
- 链接悬停时出现下划线或颜色变化。
- 面板出现时使用轻微淡入。
- 选中状态保持明确的视觉标识。
- 异步请求显示真实加载状态。
- 操作完成后展示成功或错误提示。

### 12.3 交互完整性

所有按钮、链接、菜单、标签页、筛选器和表单都必须连接实际行为。

如果现有项目具有真实业务逻辑，应优先复用原有逻辑。

禁止仅制作视觉上可操作的假按钮，禁止使用无意义的点击动画冒充功能完成。

## 十三、响应式与现代可用性

### 桌面端

- 可以使用多列布局和较密集的网页结构。
- 保留清晰的主内容区域。
- 装饰元素可以更加丰富。
- 导航和辅助区域应保持清晰。

### 平板端

- 适当减少装饰密度。
- 调整内容列宽和间距。
- 避免辅助栏挤压主要内容。

### 移动端

- 导航需要适配窄屏。
- 多列布局应合理转换。
- 贴纸与装饰元素应适当隐藏或缩小。
- 正文保持清晰可读。
- 按钮应有足够的点击区域。
- 不允许出现横向滚动条或内容被遮挡。
- 不要强行将桌面端密集布局压缩到手机屏幕上。

### 可访问性

- 正文与背景保持足够的对比度。
- 交互控件具有清晰的键盘焦点。
- 不依赖颜色单独传达状态。
- 正确设置语义化 HTML 与可访问名称。
- 支持浏览器缩放和减少动态效果。
- 像素字体不能用于长篇正文。

## 十四、工程实现约束

请在当前项目的既有技术栈、工程目录和业务结构中实现。

### 执行要求

1. 先检查现有技术栈、页面、路由、组件、样式和资源。
2. 优先复用现有组件，不要为了视觉改造重建整个项目。
3. 不擅自更换前端框架、构建工具或状态管理方案。
4. 不随意修改后端接口、数据模型、权限控制或业务逻辑。
5. 建立统一的颜色、字体、材质、间距、阴影与动效变量。
6. 将可复用的按钮、徽章、导航、标签和面板抽取为组件。
7. 避免大量重复 CSS 和随意散布的魔法数值。
8. 保留现有页面功能、数据绑定、路由和表单校验。
9. 不虚构后端接口、统计数据、页面内容或成功状态。
10. 不引入没有必要的大型依赖。
11. 确保样式不会无意中污染项目其他模块。
12. 图片、字体或外部资源加载失败时，页面仍能正常使用。

### 样式实现

- 优先使用项目已有的 CSS 方案。
- 可以使用 CSS Variables、渐变、阴影、伪元素和 SVG。
- 避免大量使用 `!important`。
- 合理控制选择器优先级。
- 注意层叠上下文、定位和 z-index。
- 为不支持高级效果的环境提供合理降级。
- 避免使用高成本滤镜造成明显性能问题。

## 十五、实施流程

### 第一步：分析项目

### 第二步：建立设计系统

先定义颜色 Token、字体字阶、金属材质、亮面按钮、面板边框、徽章、装饰图形和交互状态。

根据实际业务内容选择合适的布局，不预先固定页面数量或栏目结构。

检查不同屏幕尺寸、文字换行、装饰遮挡、资源加载、浏览器控制台和现有业务功能。

### 第六步：交付说明

说明实际修改的页面、组件、设计 Token、交互行为，以及尚未完成或需要替换的资源。

## 十六、最终验收标准

完成后必须满足：

- 第一眼具有明显的千禧年代早期互联网气质。
- 银色金属、亮面按钮、电子蓝与像素装饰之间形成统一风格。
- 正文、标题、导航、徽章和状态信息具有清晰层级。
- 复古材质不是简单地堆叠渐变、阴影与发光。
- 装饰元素不会遮挡内容或妨碍操作。
- 所有按钮和链接都有真实、合理的行为。
- 交互状态完整，键盘焦点清晰。
- 桌面端与移动端均能正常使用。
- 不虚构数据，不破坏现有业务逻辑。
- 不固定页面数量、栏目数量或组件数量。
- 代码结构清晰，设计规范可复用。

**最终目标：**让网站仿佛来自千禧年代的互联网，却拥有现代 Web 的稳定性、可访问性和响应式能力。保留早期个人主页的个性、复古数品的亮面质感，以及旧互联网特有的装饰趣味；同时让真实内容始终处于视觉中心。
````
