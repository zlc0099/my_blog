这套提示词面向电影发现平台、影评社区、流媒体内容浏览和电影资料库。它统一的是海报比例、标题与元信息层级、评分和收藏状态、筛选与搜索、详情页信息组织以及响应式规则；页面数量、栏目结构和片单数量由项目真实内容决定。

电影网站的第一视觉入口应该是海报，而不是通用后台卡片。深色背景负责建立观影氛围，金色只用于评分、收藏和精选标记，标题、年份、类型、时长和简介必须拉开层级。

## 适合什么场景

- 电影资料库、在线选片、影评社区、流媒体内容浏览。
- 需要同时承载海报发现、搜索结果、电影详情和用户评论的项目。
- 以图片内容为主，要求桌面端沉浸浏览、移动端易点击的产品。

不适合普通电商商品列表、管理后台或没有真实电影数据却需要伪造大量内容的页面。没有真实数据时，可以使用明确标记的演示内容完成视觉验证。

## 视觉构成

- **深色观影环境**：页面底、提升表面和内容表面分层，海报保持自己的色彩，不统一加滤镜。
- **海报主视觉**：优先使用接近 `2:3` 的竖版海报；剧照、横幅和推荐图使用自己的比例。
- **编辑式排版**：电影名称、评分、年份、类型、时长和简介按信息优先级排列。
- **发现效率**：横向片单用于推荐，海报网格用于筛选和搜索结果；分页、筛选和排序反馈必须真实。
- **交互状态**：收藏、评分、评论、加载、空状态和失败状态都要和真实业务一致。
- **克制装饰**：不使用霓虹发光、玻璃拟态和夸张动画掩盖信息结构。

## 使用边界

- 不把所有内容套成同一种大圆角卡片，也不把竖版海报裁成统一宽屏图。
- 标题、评分、年份、类型不能使用同等字号；长片名必须能完整查看。
- 不虚构评分、评分人数、影评、访问量或电影资料。
- 搜索、筛选、收藏、评分和评论必须接入现有逻辑；移动端不能只依赖 hover 操作。
- 海报必须有稳定比例、替代文本、懒加载和缺图占位，避免布局跳动。
- 不为了视觉效果删除原有功能，也不引入没有必要的重型依赖。

## 完整提示词

````prompt
# 前端 UI 提示词：主流电影网站排版风格

## 一、设计目标

你是一名资深前端设计师、电影网站产品设计师与交互体验工程师。

请对当前项目进行 UI 设计与实现，使其具备现代主流电影网站的视觉特征，融合电影发现平台、专业影评社区、流媒体内容浏览和电影资料库的设计语言。

设计重点包括：

- 电影海报与横向片单。
- 清晰的电影标题和元信息层级。
- 首页内容推荐与电影发现。
- 电影详情、评分、简介和演职人员信息。
- 分类导航、搜索、筛选与排序。
- 用户评分、收藏、评论等交互状态。
- 深色观影氛围与高质量图片展示。
- 桌面端、平板端和移动端的响应式排版。

整体应当像一个成熟的电影内容平台，而不是普通电商商品列表或通用后台管理系统。

**核心要求：先建立统一的排版与组件规范，再根据项目真实业务决定页面结构。不要固定页面数量、栏目数量、海报数量或卡片数量。**

---

## 二、整体视觉方向

### 2.1 风格定位

采用「深色电影资料库 + 现代流媒体内容浏览 + 专业影评社区」的融合方向。

视觉关键词：

`Cinematic UI`、`Movie Database`、`Film Discovery`、`Poster Grid`、`Editorial Typography`、`Dark Theme`、`Movie Detail`、`Rating System`、`Horizontal Carousel`、`Responsive Layout`。

视觉上应当具备以下特点：

1. 海报是内容浏览的主要视觉入口。
2. 深色背景突出电影图片与色彩。
3. 标题、年份、类型、时长、评分等信息具有清晰层级。
4. 页面拥有适度的内容密度，避免过度空旷。
5. 首页、列表页和详情页采用统一的视觉系统。
6. 交互状态明确，但不使用过量动画和装饰。
7. 保持专业、沉浸、易浏览、易发现的整体体验。

### 2.2 设计边界

避免：

- 所有内容都使用相同的大圆角卡片。
- 每个电影模块都使用相同的横向布局。
- 将电影海报裁切成统一的宽屏图片。
- 评分、年份、类型、标题全部使用同等字号。
- 大量使用霓虹描边、发光边框和玻璃拟态。
- 用夸张动画掩盖信息架构问题。
- 将电影网站设计成普通 SaaS 后台。
- 为了填满首页而生成大量重复或虚构的电影内容。

## 三、配色与设计 Token

建立统一的 CSS Variables，用于所有页面与组件。

推荐以深色电影观影环境为基础，同时为海报、评分、收藏和交互状态保留明确的强调色。

```css
:root {
  /* 页面背景 */
  --movie-bg: #101114;
  --movie-bg-elevated: #181A1F;
  --movie-surface: #202229;
  --movie-surface-hover: #292C34;

  /* 边框 */
  --movie-border: rgba(255, 255, 255, 0.10);
  --movie-border-strong: rgba(255, 255, 255, 0.18);

  /* 文字 */
  --movie-text-primary: #F5F5F7;
  --movie-text-secondary: #B3B5BD;
  --movie-text-muted: #858995;

  /* 强调色 */
  --movie-accent: #E5B85C;
  --movie-accent-hover: #F1C875;
  --movie-accent-soft: rgba(229, 184, 92, 0.14);

  /* 状态 */
  --movie-success: #61B995;
  --movie-warning: #E6B85D;
  --movie-danger: #E26D76;
  --movie-info: #72A9E8;

  /* 布局 */
  --movie-radius-sm: 6px;
  --movie-radius-md: 10px;
  --movie-radius-lg: 16px;

  /* 阴影 */
  --movie-shadow:
    0 8px 28px rgba(0, 0, 0, 0.24);

  /* 动效 */
  --movie-transition-fast: 150ms ease;
  --movie-transition-normal: 240ms ease;
}
```

### 配色使用规范

- 深色背景用于建立电影观影氛围。
- 更亮的表面色用于筛选栏、弹窗和内容容器。
- 白色与浅灰色用于标题和主要信息。
- 中灰色用于年份、导演、类型等辅助信息。
- 金色可用于评分、收藏强调或精选标记，但不应滥用。
- 绿色、红色和蓝色用于有明确语义的状态反馈。
- 海报本身拥有独立色彩，不应给所有图片添加统一的强色滤镜。

如果项目已有成熟的主题色，应优先在现有配色基础上建立统一 Token，而不是强行替换整个品牌视觉。

## 四、字体与文字层级

### 4.1 字体体系

使用清晰、现代、适合长时间浏览的字体。

```css
:root {
  --font-movie-heading:
    "Inter",
    "PingFang SC",
    "Microsoft YaHei",
    sans-serif;

  --font-movie-body:
    "Inter",
    "PingFang SC",
    "Microsoft YaHei",
    sans-serif;

  --font-movie-metadata:
    "Inter",
    "Arial",
    sans-serif;
}
```

如果项目需要更具电影杂志气质的标题，可以为部分英文片名使用衬线字体，但不应影响中文内容的阅读一致性。

### 4.2 字阶规范

| 层级 | 建议字号 | 用途 |
|---|---:|---|
| Hero Title | 36–56px | 首页主视觉电影标题 |
| H1 | 30–40px | 电影详情页主标题 |
| H2 | 22–28px | 主要内容分区 |
| H3 | 17–21px | 片单标题、子区域标题 |
| Card Title | 14–17px | 海报下方电影标题 |
| Body | 14–16px | 简介、评论与正文 |
| Metadata | 12–14px | 年份、时长、类型 |
| Caption | 11–12px | 辅助标记和次级说明 |

实际字号应根据屏幕尺寸和文本长度调整。

### 4.3 文字层级规则

电影信息应遵循以下优先级：

1. 电影名称。
2. 海报或主视觉。
3. 评分或其他核心指标。
4. 年份、类型、时长等元信息。
5. 简介、导演和演职人员等扩展信息。

不要将所有信息堆在海报下方。

电影名称较长时，应采用合理换行或行数限制；同时确保完整片名可以通过详情页或可访问文本查看。

## 五、全局页面布局

### 5.1 内容容器

采用稳定的内容最大宽度与响应式边距。

建议：

```css
.movie-container {
  width: min(100% - 48px, 1440px);
  margin-inline: auto;
}

@media (max-width: 768px) {
  .movie-container {
    width: min(100% - 32px, 1440px);
  }
}
```

可根据项目实际布局调整最大宽度和边距。

### 5.2 页面结构原则

根据业务内容组合适合的区域，例如：

- 顶部导航。
- 搜索入口。
- 主视觉推荐。
- 电影发现区域。
- 横向电影片单。
- 海报网格。
- 分类与筛选。
- 电影详情。
- 用户评论与评分。
- 分页或加载更多。
- 页脚与辅助导航。

这些只是可选结构，不要求所有页面全部包含。

### 5.3 内容密度

- 首页可以采用较丰富的内容组合。
- 列表页优先保证筛选和浏览效率。
- 详情页突出电影主信息。
- 评论页优先保证阅读体验。
- 搜索页应突出关键词、结果数量和筛选条件。
- 空状态应解释当前没有结果的原因，并提供下一步操作。

不要为了视觉一致而将所有页面强制改成同一种布局。

## 六、顶部导航与搜索

### 6.1 顶部导航

导航应简洁、清晰，并体现电影内容平台的属性。

可以根据项目实际功能展示：

- 品牌标识。
- 电影发现入口。
- 分类或排行榜入口。
- 搜索入口。
- 用户个人区域。
- 收藏或个人片单入口。

导航项目应来自真实业务，不要为了填充导航而增加无效栏目。

### 6.2 搜索框

搜索是电影网站的重要功能。

设计要求：

- 搜索框具有明确的输入提示。
- 聚焦状态应清晰。
- 支持提交与清空。
- 搜索结果应能够反馈关键词。
- 如果项目支持自动补全，应区分电影、人物和其他结果类型。
- 无结果时显示友好提示。
- 搜索中应展示真实的加载状态。
- 移动端应提供便于点击的搜索入口。

搜索框不能只有视觉效果，必须接入项目实际的搜索逻辑。

## 七、电影海报卡片

电影海报卡片是整个设计系统的核心组件。

### 7.1 海报比例

电影海报优先采用接近 `2:3` 的竖向比例。

```css
.movie-poster {
  aspect-ratio: 2 / 3;
  overflow: hidden;
  background: var(--movie-surface);
  border-radius: var(--movie-radius-md);
}

.movie-poster img {
  display: block;
  width: 100%;
  height: 100%;
  object-fit: cover;
}
```

不要将竖版海报统一裁切为宽屏缩略图。

如果内容本身属于剧集横幅、电影剧照或横向推荐图，则应使用适合该内容的图片比例，而不是强制所有图片采用相同尺寸。

### 7.2 卡片信息

根据项目的数据结构，可以包含：

- 电影海报。
- 电影名称。
- 原始名称。
- 上映年份。
- 评分。
- 电影类型。
- 收藏状态。
- 用户评分状态。

不要求每张卡片展示全部信息。应根据页面密度和浏览目的选择合适的字段。

### 7.3 默认状态

- 海报清晰完整。
- 标题具有足够对比度。
- 元信息字号小于标题。
- 卡片背景与页面背景存在适度区分。
- 不使用过重的阴影。
- 不要给每张海报增加无意义的装饰标签。

### 7.4 悬停状态

桌面端悬停时可以：

- 轻微放大海报。
- 显示简短简介。
- 显示评分与年份。
- 出现收藏操作。
- 显示进入详情的提示。

悬停层应有明确的背景和文字对比度，不得遮挡重要内容。

移动端没有悬停状态，因此关键操作必须通过点击、独立按钮或详情页实现。

### 7.5 加载与缺图

- 海报加载中使用统一占位背景。
- 图片加载失败时显示清晰的默认占位图。
- 避免因图片比例不一致造成页面布局跳动。
- 如果项目使用懒加载，应保证首屏主要内容优先加载。

## 八、横向电影片单

横向片单适合首页推荐、热门电影、近期上映、经典电影或个性化收藏等场景。

### 排版规则

- 每个片单应具有明确的标题。
- 可在标题区域展示简短说明或查看更多入口。
- 海报应保持统一比例。
- 卡片之间保留稳定间距。
- 允许横向滚动，但必须保证滚动方向和交互方式清晰。
- 可以提供左右切换按钮，但仅在需要且适合的场景使用。
- 不能强制每个片单展示相同数量的电影。

### 交互要求

- 支持鼠标、触控板和触屏操作。
- 左右切换按钮需要正确处理边界状态。
- 横向滚动不应影响页面正常纵向滚动。
- 键盘用户应能访问片单中的链接和操作。
- 不应隐藏用户无法通过其他方式访问的内容。

如果项目已有成熟的轮播组件，应优先复用，而不是重复实现一套不兼容的交互。

## 九、电影网格与筛选列表

电影发现和搜索结果通常需要更高的浏览效率。

### 9.1 网格布局

使用 CSS Grid 或项目现有的布局系统，根据屏幕宽度调整列数。

```css
.movie-grid {
  display: grid;
  grid-template-columns: repeat(
    auto-fill,
    minmax(150px, 1fr)
  );
  gap: 28px 18px;
}

@media (max-width: 640px) {
  .movie-grid {
    grid-template-columns: repeat(2, minmax(0, 1fr));
    gap: 20px 12px;
  }
}
```

以上只是基础示例。实际列数、卡片宽度和间距应结合页面容器、海报尺寸和信息密度调整。

### 9.2 筛选与排序

如果项目存在相应功能，可以提供：

- 年份筛选。
- 类型筛选。
- 评分区间。
- 地区筛选。
- 排序方式。
- 搜索关键词。
- 已选条件标签。
- 清除筛选操作。

筛选控件应具有统一的高度、间距、边框和状态。

不要一次性堆叠过多筛选项。复杂筛选可采用折叠区域、弹出面板或移动端抽屉。

### 9.3 筛选状态

需要明确展示：

- 当前筛选条件。
- 当前排序方式。
- 加载状态。
- 查询结果数量（仅在真实数据可用时）。
- 无结果状态。
- 清除筛选后的反馈。

如果筛选条件影响 URL，应合理处理参数同步、刷新和浏览器前进后退。

## 十、电影详情页

电影详情页应具有明显的视觉重点和清晰的信息阅读顺序。

### 10.1 主视觉区域

根据实际数据，可以组合：

- 背景剧照或横幅。
- 电影海报。
- 电影名称。
- 原始名称。
- 上映年份。
- 类型与时长。
- 评分与评分人数。
- 简介。
- 收藏或添加片单操作。

不要强制所有字段都挤在首屏。应根据电影信息的重要性决定展示优先级。

### 10.2 背景剧照

如果使用电影剧照作为详情背景：

- 使用适度的暗色渐变保证文字可读。
- 避免背景细节与标题冲突。
- 允许主视觉背景采用横向比例。
- 主海报仍应保持自身比例。
- 图片加载失败时应有合理的背景降级。

### 10.3 信息区域

详情页可根据项目真实数据展示：

- 剧情简介。
- 导演。
- 编剧。
- 演员。
- 类型。
- 上映日期。
- 制片地区。
- 片长。
- 原始语言。
- 评分分布。
- 用户短评。
- 相关电影。

不要为不存在的数据字段显示空白标签，也不要用虚构信息填满页面。

### 10.4 页面排版

- 主标题应具有最高的文本优先级。
- 核心评分应容易找到。
- 简介应控制行宽，方便阅读。
- 演职人员列表可以使用横向滚动或适当的网格。
- 相关电影可以复用统一的海报卡片组件。
- 长内容应自然延展，不能依赖固定高度容器强行裁切。

---

## 十一、评分与用户操作

### 11.1 评分显示

评分组件应清楚区分：

- 平台综合评分。
- 用户个人评分。
- 评分人数。
- 暂无评分状态。

不同评分体系不可混为一谈。

如果项目采用十分制、百分制或其他量表，应按照真实业务规则显示，不得擅自改变计算方式。

### 11.2 评分视觉

- 评分数值可以使用更明显的字重。
- 星级图标仅在评分体系确实采用星级时使用。
- 金色强调色适合评分，但不应让所有评分都变成高亮状态。
- 无评分时显示中性状态。
- 不应将用户个人评分与平台平均分显示为同一个指标。

### 11.3 收藏与片单

如果项目支持收藏或个人片单：

- 明确区分已收藏和未收藏。
- 点击后提供即时、准确的状态反馈。
- 异步保存时显示真实加载状态。
- 保存失败时恢复合理的 UI 状态。
- 需要登录时按照项目现有权限规则处理。
- 不要使用没有业务含义的装饰按钮冒充收藏功能。

---

## 十二、影评与评论区域

评论区域应突出可读性与内容层级，而不是让用户面对大量相同样式的卡片。

可以根据实际功能包含：

- 用户头像。
- 用户名。
- 评分。
- 发布时间。
- 评论正文。
- 点赞或有用反馈。
- 排序方式。
- 展开或折叠。
- 评论输入区域。

### 设计要求

- 用户信息与评论正文应具有清晰层级。
- 长评论应自然换行。
- 时间和辅助操作应降低视觉权重。
- 评论内容应避免被过度裁切。
- 没有评论时提供合理的空状态。
- 发表评论、点赞等操作必须连接实际业务。
- 错误和成功提示应明确，不得伪造操作结果。

---

## 十三、按钮、标签与通用组件

建立统一的组件规范。

### 按钮

- Primary：主要操作。
- Secondary：次要操作。
- Ghost：低干扰操作。
- Icon Button：图标操作。
- Disabled：不可用状态。

不同按钮的层级应清晰，不要让所有操作都具有相同的强调程度。

### 标签

标签可用于电影类型、内容分类、上映年份、精选状态和用户自定义标记。

要求：

- 高度与内边距统一。
- 字号小于正文。
- 颜色与语义保持一致。
- 不要让标签抢过电影名称。
- 标签过多时，应采用合理的折叠或展示策略。

### 通用状态

所有适用的组件都需要考虑：

- Default。
- Hover。
- Focus。
- Active。
- Selected。
- Disabled。
- Loading。
- Success。
- Error。
- Empty。

状态反馈应与实际业务状态一致。

## 十四、响应式设计

### 桌面端

- 充分利用宽屏空间展示海报和辅助信息。
- 主导航、搜索和用户区域保持清晰。
- 详情页可以采用海报与信息并排的布局。
- 电影网格保持适当的列数与间距。

### 平板端

- 减少不必要的辅助区域。
- 重新计算海报列数。
- 适当缩小横向片单的卡片宽度。
- 避免筛选栏挤压内容区域。

### 移动端

- 电影网格优先采用易浏览的两列或其他合理布局。
- 详情页可以将海报与信息改为上下布局。
- 搜索和筛选操作应方便单手点击。
- 横向片单需要适配触摸滚动。
- 不要把桌面端的所有内容直接压缩。
- 长片名和长简介不能造成横向溢出。
- 重要操作不能只存在于鼠标悬停中。
- 保证按钮点击区域足够大。

---

## 十五、可访问性与性能

### 可访问性

- 电影海报根据实际内容提供合理的替代文本。
- 装饰性图片使用适当的空替代文本。
- 评分不能只通过颜色表达。
- 所有交互控件应具有可访问名称。
- 键盘焦点必须清晰。
- 页面标题层级应符合语义。
- 支持浏览器缩放与减少动态效果。

### 性能

- 对海报设置稳定的宽高比例，减少布局跳动。
- 合理使用图片懒加载。
- 优先加载首屏核心图片。
- 避免对大量海报同时执行复杂动画。
- 使用合适的图片尺寸与格式。
- 避免不必要的大型依赖。
- 对分页或无限滚动进行合理的数据加载控制。
- 保持列表滚动与搜索交互流畅。

## 十六、工程实现约束

请在当前项目既有技术栈与工程结构内实现。

1. 首先检查项目框架、目录、路由、组件、样式体系和数据来源。
2. 优先复用现有组件、业务逻辑和接口。
3. 不擅自替换前端框架、构建工具或状态管理方案。
4. 不擅自修改后端 API、数据库字段、评分计算规则或权限逻辑。
5. 建立统一的颜色、字体、间距、圆角和动效 Token。
6. 将电影海报卡片、片单、评分、标签、按钮和状态提示封装为可复用组件。
7. 组件应支持真实数据，不要把示例电影硬编码到所有页面。
8. 对空字段、图片缺失、接口失败和无搜索结果进行合理处理。
9. 不得虚构评分、影评、访问量或其他业务数据。
10. 不要为了视觉效果删除原有功能。
11. 不引入没有必要的重型依赖。
12. 确保修改后项目可以正常运行，且没有明显控制台错误。

如果项目没有真实电影数据，可以使用明确标记的演示数据完成开发验证；演示数据不能伪装成真实平台数据。

## 十七、实施流程

### 第一步：项目分析

检查现有页面、路由、业务模块、数据结构和技术栈。

### 第二步：建立 UI 规范

统一背景色、文字色、字体层级、海报比例、卡片间距、按钮、评分、标签和状态反馈。

### 第三步：改造核心页面

根据项目真实需求，优先处理最重要的电影浏览入口、搜索结果、电影详情或个人内容区域，不强制所有页面使用同一布局。

### 第四步：完善交互

检查搜索、筛选、排序、分页、收藏、评分、评论和导航等实际功能。

### 第五步：响应式测试

验证桌面端、平板端和移动端的海报比例、布局密度、操作空间和文本换行。

### 第六步：最终检查

检查图片加载、空状态、错误状态、交互反馈、业务兼容性和代码质量。

完成后简要列出修改内容、复用组件、交互实现情况以及遗留问题。

## 十八、最终验收标准

- 具有成熟电影发现平台的整体视觉气质。
- 海报比例正确，电影图片展示清晰。
- 电影名称、评分、年份、类型和简介层级明确。
- 首页、列表页与详情页使用统一的视觉系统。
- 横向片单和海报网格均具有合理的间距与响应式表现。
- 搜索、筛选和排序状态清晰。
- 收藏、评分、评论等操作与实际业务一致。
- 图片缺失、无结果、加载失败等状态有合理处理。
- 桌面端与移动端均可正常浏览和操作。
- 不固定页面数量、栏目数量、卡片数量或片单数量。
- 不虚构业务数据，不破坏原有工程结构。
- 代码可维护、组件可复用、交互真实有效。

**最终目标：**构建一套兼具电影氛围、内容发现效率、专业排版和现代可用性的电影网站 UI。以电影海报建立第一视觉焦点，以标题和元信息组织内容，以筛选和搜索提升发现效率，以详情与评论承载深度信息，并通过统一的组件和交互规范形成完整的产品体验。
````
