这套规范用于「黑金工业科技 + 深色科技蓝」的数据大屏。它统一的是配色、字体、面板、图表、数字和动态效果；业务模块、面板数量、图表类型、区域比例和信息结构由真实业务决定，不预设三列布局、固定统计卡或六宫格。

## 适合什么场景

- 智慧城市、城市运行监测、道路巡查与交通监控。
- 企业经营分析、运营指挥中心、生产/设备/运维监控。
- 项目进度、任务执行、工单统计和实时态势感知。

## 视觉层级

1. 环境层：深黑、深蓝黑背景，形成稳定基底。
2. 结构层：面板边框、分隔线、网格和区域轮廓。
3. 数据层：数值、趋势、图表、指标和状态。
4. 强调层：少量金色、亮蓝和高亮状态，用来吸引注意力。

数据是画面主角，装饰只负责科技感和层级；不要大面积高饱和渐变、所有面板发光、所有标题加辉光、满屏电路纹理和持续旋转动画。

## 配色 Token

黑金：
- 主背景 `#080B10`，深背景 `#05070B`。
- 面板 `#0D131C`，强调面板 `#111A25`，面板边框 `#263341`，网格 `#15202B`。
- 金色 `#D6B36A`，亮金 `#F0D38A`，暗金 `#8F7848`，金色浅底 `rgba(214,179,106,.10)`。
- 主文字 `#E8EDF4`，次要 `#A4B0BE`，辅助 `#6F7D8D`，分割线 `#202C38`。

科技蓝：
- 主蓝 `#2589FF`，亮蓝 `#49B7FF`，浅蓝 `#83D5FF`，深蓝 `#1455A0`，蓝色浅底 `rgba(37,137,255,.10)`。
- 青色 `#35D4E8`，暗青 `#248B9B`；青色只用于第二数据系列，不滥用。

状态色：正常 `#35C98A`，关注 `#E7B65A`，异常 `#F06464`，信息 `#49B7FF`，中性 `#8492A6`。状态必须结合业务定义，不能把预警等级、完成状态和任务进度混为一谈；异常不能靠持续闪烁表达。

比例参考：约 70% 深色背景和低对比结构，20% 面板与常规数据，10% 关键数值、状态色和强调。金色只给高价值信息，蓝色负责数据表达，金色和蓝色不要平均分配。

## 字体与数字层级

- 字体栈：`"DIN Alternate", "Roboto", "Segoe UI", "Microsoft YaHei", sans-serif`；数字可用工业感字体，中文标题必须清晰。
- 大屏主标题 28–36/600；核心指标 36–56/600；次级指标 24–36/600；面板标题 16–20/600；列表主值 14–18/500；坐标标签 11–13/400；辅助说明 12–14/400；角标 10–12/400。
- 核心指标可包含名称、数值、单位、同比/环比、目标值、更新时间，但不要为了填满组件虚构数据。
- 数值比说明突出；单位紧邻数值但不抢焦点；增长率说明比较口径；正负变化不能只靠颜色；千分位、小数、百分号、单位统一格式化；缺失值不能显示为 0。

## 面板与网格

- 面板底 `#0D131C`，1px `#263341` 边框，圆角 4–8px，内边距 16–24px，默认不加明显阴影。
- 基础面板低对比边框、不发光；重点面板可用较亮的蓝/金局部边线；浮层用更清晰的边界和适度阴影。
- 允许单侧短边线、标题旁细线、局部切角、少量定位标记和金色强调线；不要每个面板换一种形状，不要大面积双层边框，不要持续闪烁装饰线。
- 普通面板圆角 4–6，重点面板 4–6，浮层 6–8；辉光只给少数重点元素。
- 布局用 CSS Grid/Flex 和比例、`minmax()`，重要区域获得更大空间；不预设面板数量，不固定三列/六宫格；不要大量绝对定位拼接大屏，不要用隐藏溢出来掩盖布局问题。
- 16:9（如 1920×1080）可作为标准横向屏参考，实际以展示设备为准；图表容器监听尺寸变化并重绘，处理浏览器缩放、全屏切换和窗口变化。

## 图表与数据表达

- 图表背景透明或接近面板深色；网格线低对比蓝灰；坐标轴不过度突出；图例位置合理；系列颜色稳定；只有确有需要才用渐变填充。
- 按数据关系选图：时间变化用折线/面积，类别比较用横向条形/柱状，构成比例用环形/堆叠，空间分布用地图/热力，实时监测用趋势/状态列表，排名用条形/列表。
- 坐标文字 11–12px，单位清楚，网格线不能比数据线更显眼，时间轴刻度自动调整，避免过密标签和被面板截断。
- 系列色顺序：科技蓝、青色、低饱和金色、绿色、经过对比验证的辅助色；同一指标跨图表保持颜色一致，金色不要随机分配，多系列必须配图例，颜色不足时加线型、点形或标签。
- 折线主线 2px，次要 1.5px，数据点适度弱化，重点节点可标记，面积填充低透明度；柱体宽度和间距稳定，重点柱可用金色/亮蓝；环形中心数值与含义一致，小占比不能消失；不要立体饼图、装饰仪表盘和无意义 3D。
- 交互提示用深色背景、细边框、准确数值和单位，不遮挡关键数据点；纯展示大屏不强加复杂交互。

## 地图、实时与动画

- 地图只在业务涉及地理空间时使用；底图不过亮，道路/边界/区域层级清晰，关键位置用蓝/金有限强调，异常点用状态色；图例和比例清楚；地图数据、坐标、区域名称必须来自真实业务，不能虚构位置。
- 实时数据清晰显示更新时间；异常可有轻量提示；不要让整页闪烁；数字变化用克制过渡；高频更新避免整页重绘；接口失败显示异常状态和最后有效数据时间；区分实时、历史、缓存和估算值，不把旧数据伪装成最新。
- 动画：轻量交互 120–180ms，面板切换 180–240ms，指标变化按刷新频率；禁止无限旋转、全屏扫描、所有数字持续滚动、面板持续呼吸、每次更新重播入场动画；尊重 `prefers-reduced-motion`。

## 标题、标注与图例

- 面板标题 16–20/600，用主文字色，可加短蓝线或小型标记；不要每个标题一种装饰；标题要准确表达内容，必要时显示统计口径、时间范围或单位。
- 标注优先重点，文字 11–13px，数值和单位合理分组，避免重叠，颜色与背景有足够对比；不要给所有点永久加数值，只强调峰值、异常和关键节点。
- 图例靠近图表，颜色与真实系列一致，系列多时合理换行；不要因装饰省略图例；图例开关要有反馈。

## 数据真实性与工程约束

- 优先复用现有接口、数据模型和业务逻辑；不虚构统计数字、增长率、排名和地图坐标；不用随机数据填充正式页面。
- 无数据展示空状态，加载有适度指示，失败有明确错误，缺失值不等于 0，百分比和汇总遵循真实口径，时间范围和单位清晰；模拟数据必须标注“演示数据”并与正式接口隔离。
- 改造前检查框架、图表库、路由、主题、请求方式、实时刷新、地图来源和全屏/缩放逻辑；不擅自换技术栈。
- 用 CSS Variables 或现有主题统一背景、面板、金/蓝强调、状态色、字阶、内边距、网格、边框、圆角、阴影、辉光、动画和图表系列色。
- 用 CSS Grid/Flex，避免大量绝对定位；图表实例正确初始化、更新、销毁和 resize；防止容器高度为 0、动态数据导致布局抖动。
- 优先用现有图表库（如 ECharts）建立统一主题；不重复引入多个图表库；保留路由、接口、DTO/VO、权限和业务规则；不删功能；抽取面板标题、指标、图表容器和图例组件，避免一个巨大组件。

## 验收

- 视觉：黑金与科技蓝分工明确；背景够深但文字清晰；金色只做关键强调；面板边框统一不过度发光；数字层级、单位、说明完整；图表坐标和图例可读；面板数量和布局按业务决定；没有装饰堆砌和无意义动画。
- 数据：指标来自真实数据或明确标注的演示数据；单位、时间、口径正确；缺失值和零值区分；异常状态映射符合业务；图表与指标数字一致。
- 工程：复用现有技术栈；Token 统一；图表能初始化、更新、销毁；全屏和窗口变化正常；无文字重叠、图表裁切和面板溢出；原业务逻辑和接口未被擅自修改；实际测试结果如实记录。

## 常用短句

- “用黑色建立空间，用科技蓝组织数据，用金色强调价值。”
- “面板数量、图表类型按业务决定，不要预设三列或六宫格。”
- “金色只给关键数字和重点节点，蓝色负责数据表达。”
- “数据必须来自真实接口或明确标注的演示数据。”

下面是这份规范的完整提示词，可以直接整段复制给 Agent。它只定义视觉语言和数据表达，不预设面板数量和业务栏目。

```prompt
# 前端 UI 提示词：黑金 / 科技蓝数据大屏设计规范

## 一、角色定位与设计目标

你是一名资深数据可视化设计师、企业级大屏 UI 设计师和前端工程师。

请基于当前项目的业务目标、数据类型和现有技术栈，构建一套具有统一视觉语言的高保真数据大屏。

设计风格为「黑金工业科技」与「深色科技蓝」融合的现代数据可视化风格。

适用场景包括：
- 智慧城市与城市运行监测。
- 道路巡查与交通运行监控。
- 企业经营分析与运营指挥中心。
- 生产监控、设备监测与运维分析。
- 项目进度、任务执行与工单统计。
- 实时数据展示、综合态势感知和业务分析。

核心视觉关键词：

深色背景、精密网格、科技蓝线框、低亮度金色强调、清晰数字层级、克制的辉光、数据优先、空间秩序、专业工业感。

**核心原则：统一视觉语言，不限制面板数量，不预设业务栏目，不强制图表类型。**

大屏布局必须根据真实业务的重要程度、数据关系、屏幕比例和用户的观看距离动态决定。不得为了套用模板，机械地生成固定的三列布局、固定数量的统计卡片或固定的六宫格面板。

## 二、整体视觉方向

### 2.1 视觉气质

整体应具有专业指挥中心和工业数据终端的视觉气质，而不是普通网页后台的简单深色主题。

视觉层级分为四层：

1. **环境层：** 深黑、深蓝黑背景，形成稳定的视觉基底。
2. **结构层：** 面板边框、分隔线、网格和区域轮廓。
3. **数据层：** 数值、趋势、图表、指标和状态。
4. **强调层：** 少量金色、亮蓝色和高亮状态，用于吸引注意力。

数据本身必须是画面的主角，装饰元素只负责建立科技感和信息层级。

### 2.2 禁止的视觉表现

- 大面积高饱和渐变背景。
- 所有面板都使用发光边框。
- 所有标题都添加金色或蓝色辉光。
- 过度密集的电路纹理、粒子、扫描线。
- 大量旋转动画和无意义的数字跳动。
- 所有图表都使用相同的蓝色渐变。
- 每个指标都设计成独立的悬浮卡片。
- 为了视觉效果而牺牲图表标注、数据精度和文字可读性。
- 过度使用立体柱状图、3D 饼图和装饰性仪表盘。
- 不符合实际数据关系的地图、排行或趋势图。

最终效果应当高级、克制、清晰，能够长时间展示和观看。

---

## 三、色彩设计系统

必须建立统一的设计 Token。所有页面、面板、数字、图表和状态标识都应使用统一的颜色变量。

### 3.1 黑金主色方案

以深黑、石墨黑和低饱和金色构建工业科技氛围。

| Token | 色值 | 使用场景 |
|---|---|---|
| `--screen-bg` | `#080B10` | 大屏主背景 |
| `--screen-bg-deep` | `#05070B` | 深色背景区域 |
| `--panel-bg` | `#0D131C` | 普通面板背景 |
| `--panel-bg-raised` | `#111A25` | 强调面板背景 |
| `--panel-border` | `#263341` | 面板基础边框 |
| `--grid-color` | `#15202B` | 背景网格 |
| `--gold-primary` | `#D6B36A` | 核心强调色 |
| `--gold-bright` | `#F0D38A` | 重点数字与少量高亮 |
| `--gold-muted` | `#8F7848` | 次级金色标识 |
| `--gold-soft` | `#D6B36A1A` | 金色浅背景 |
| `--text-primary` | `#E8EDF4` | 主要文字 |
| `--text-secondary` | `#A4B0BE` | 次级文字 |
| `--text-muted` | `#6F7D8D` | 辅助文字 |
| `--divider-color` | `#202C38` | 分割线 |

金色只用于具有较高业务价值的信息，例如核心指标、关键节点、重要目标和精选强调标识。

禁止使用金色覆盖整个标题栏、所有按钮、所有图表线条和全部边框。

### 3.2 科技蓝配色方案

科技蓝用于数据可视化、动态状态和主要交互反馈。

| Token | 色值 | 使用场景 |
|---|---|---|
| `--blue-primary` | `#2589FF` | 主数据色 |
| `--blue-bright` | `#49B7FF` | 重点数据线、关键节点 |
| `--blue-light` | `#83D5FF` | 高亮辅助信息 |
| `--blue-deep` | `#1455A0` | 次级图形和背景层 |
| `--blue-soft` | `#2589FF1A` | 蓝色半透明区域 |
| `--cyan-primary` | `#35D4E8` | 第二数据系列 |
| `--cyan-muted` | `#248B9B` | 次级趋势或辅助图形 |

使用原则：
1. 科技蓝是主要的数据可视化颜色。
2. 金色负责重点强调，蓝色负责结构和数据表达。
3. 青色用于区分必要的第二数据系列，不应滥用。
4. 同一图表中的颜色必须具有稳定语义。
5. 不得仅通过色彩区分关键业务状态。
6. 同一类指标在不同页面中应尽量使用一致的颜色。
7. 金色与蓝色的使用比例应服务于业务优先级，而不是追求平均分布。

### 3.3 业务状态色

| 状态 | 颜色 | 建议用途 |
|---|---|---|
| 正常 | `#35C98A` | 正常运行、达标 |
| 关注 | `#E7B65A` | 预警、接近阈值 |
| 异常 | `#F06464` | 故障、超限、严重异常 |
| 信息 | `#49B7FF` | 处理中、实时更新 |
| 中性 | `#8492A6` | 未开始、无数据 |

实际颜色必须结合业务状态定义，不得将预警等级、完成状态和任务进度混为一谈。

异常信息可以通过颜色、图标、文字和位置共同表达，但不得通过持续闪烁制造不必要的视觉干扰。

### 3.4 颜色使用比例

推荐将视觉重心控制在以下范围：

- 约 70%：深色背景与低对比度结构。
- 约 20%：面板、图表主体和常规数据。
- 约 10%：关键数值、状态色和重点强调。

这是一项视觉平衡参考，而非强制的像素占比。

如果真实业务包含大量异常信息，状态色可以合理增加；如果大屏以长期趋势分析为主，则应优先保持稳定、低干扰的配色。

## 四、字体与数字层级

### 4.1 字体规范

优先采用适合中文数据展示的系统字体：

`"DIN Alternate", "Roboto", "Segoe UI", "Microsoft YaHei", sans-serif`

如果项目已有数字字体或品牌字体，应优先复用。

数字可以采用偏工业感的字体，但中文标题必须保证清晰可读。

### 4.2 字阶系统

| 层级 | 建议字号 | 字重 | 使用场景 |
|---|---:|---:|---|
| 大屏主标题 | 28–36px | 600 | 页面核心标题 |
| 核心指标数字 | 36–56px | 600 | 最重要的业务数据 |
| 次级指标数字 | 24–36px | 600 | 普通关键指标 |
| 图表区标题 | 16–20px | 600 | 面板标题 |
| 数据列表主值 | 14–18px | 500 | 列表和明细 |
| 图表坐标标签 | 11–13px | 400 | 轴标签、刻度 |
| 辅助说明 | 12–14px | 400 | 单位、口径、时间 |
| 角标与微型标签 | 10–12px | 400 | 次级标识 |

具体字号应根据最终显示分辨率、观看距离和容器尺寸进行调整。

### 4.3 核心数字展示

核心指标必须采用明确的数字层级。

每个核心指标根据实际数据结构，可以包含：
- 指标名称。
- 指标数值。
- 计量单位。
- 同比或环比变化。
- 目标值或完成率。
- 数据更新时间。

以上元素均为可选项，不得为了填满组件而虚构数据。

展示规则：
1. 数值比说明文字更突出。
2. 单位应紧邻数值，但不能与数值争夺视觉焦点。
3. 增长率必须明确说明比较口径。
4. 正负变化不能只依赖颜色表达。
5. 大数字应采用稳定的数字对齐方式。
6. 千分位、小数位、百分号和单位必须按业务规则统一格式化。
7. 数值变化时优先采用平滑更新，避免高频跳动。
8. 没有真实数据时显示明确的无数据状态，不得用随机数字填充。

### 4.4 数字格式规则

- 数量：根据业务规模决定是否使用千分位。
- 百分比：明确小数位规则。
- 金额：明确货币单位和精度。
- 时间：统一日期与时分秒格式。
- 大规模数值：可以使用万、百万等缩写，但必须确保口径一致。
- 实时指标：可展示最后更新时间或实时状态。
- 缺失数据：使用统一占位符，不得将缺失值误显示为零。

所有格式化必须由统一工具函数或现有业务格式化逻辑处理，不能每个组件单独实现。

---

## 五、面板边框与表面层级

### 5.1 面板基础规范

推荐基础面板：

- 背景：`#0D131C`。
- 边框：`1px solid #263341`。
- 圆角：4–8px。
- 内边距：16–24px。
- 标题区高度：根据标题、操作和内容决定。
- 默认无明显阴影。

面板边框应具有结构感，但不应让每个面板都像发光的设备仪表。

### 5.2 边框层级

分为三类：

**基础面板**
- 使用低对比度边框。
- 不使用发光效果。
- 用于常规数据区域。

**重点面板**
- 可以使用较亮的蓝色或金色局部边线。
- 只用于核心业务指标、重要异常或重点分析区域。
- 不得同时叠加多层高亮边框。

**浮层面板**
- 用于提示框、悬浮详情和交互弹窗。
- 使用更清晰的边界和适度阴影。
- 必须保持与背景的对比度。

### 5.3 装饰性边角

允许使用工业科技风的局部装饰，例如：
- 单侧短边线。
- 标题旁的细线。
- 局部切角。
- 细小的蓝色定位标记。
- 少量金色强调线。

但必须遵守：
1. 装饰不应影响文字和图表。
2. 不得每个面板都使用不同的边框形状。
3. 不得使用大面积双层边框。
4. 不得使用持续闪烁的装饰线。
5. 边框装饰不能取代真正的信息层级。
6. 如果项目使用纯 CSS 实现装饰，应优先使用伪元素，避免增加无意义的 DOM。

### 5.4 圆角和阴影

- 普通面板圆角：4–6px。
- 重点面板圆角：4–6px。
- 浮层圆角：6–8px。
- 普通面板不使用强烈投影。
- 浮层可以使用低透明度深色阴影。
- 蓝色或金色辉光只允许用于少数重点元素。

严禁将所有容器都做成圆润的卡片，也不要将所有边框设计为霓虹灯效果。

---

## 六、网格布局与空间组织

### 6.1 布局原则

大屏必须根据业务数据的优先级和关联关系决定布局，而不是根据预设模板分配固定数量的面板。

允许使用：
- 单一主视觉区域。
- 多列数据布局。
- 主图表加辅助图表。
- 地图与统计信息组合。
- 时间序列与事件列表组合。
- 多区域监测视图。
- 不规则分区布局。
- 重点指标与明细区域组合。

这些是可选布局模式，不是固定页面结构。

### 6.2 网格系统

建议使用 CSS Grid 或 Flexbox 建立响应式布局。

布局要求：
1. 根据实际屏幕宽高比确定内容区域。
2. 优先使用比例布局和 `minmax()` 控制区域。
3. 重要区域获得更大的可用空间。
4. 次要信息不应挤压主图表。
5. 面板之间保持统一间距。
6. 同类面板的标题和内容起始位置应尽量对齐。
7. 面板高度应满足内容展示需求。
8. 不得使用大量固定像素定位来拼接整张大屏。
9. 不得因某个面板数据增多而造成其他区域重叠。
10. 不得通过隐藏溢出内容掩盖布局问题。

### 6.3 屏幕比例与分辨率

优先考虑项目实际使用的展示环境。

如果项目面向标准横向显示屏，可以优先兼容 16:9 比例，例如 1920×1080；如果实际展示设备使用其他比例，应以实际环境为准。

适配规则：
- 使用相对布局，而不是将所有元素绝对定位。
- 对主要内容区设置合理的最小尺寸。
- 关键指标在窗口变化时应保持清晰。
- 图表容器应监听尺寸变化并正确重绘。
- 不得因缩放导致文字过小、图表标签重叠或面板超出视口。
- 必须处理浏览器缩放、全屏切换和窗口尺寸变化。
- 不得将页面缩放作为解决所有适配问题的唯一方式。

### 6.4 内容密度

每个面板都必须有明确的数据目的。

规则：
1. 不为了视觉平衡而添加没有业务意义的面板。
2. 不重复展示相同指标。
3. 不在一个面板中塞入过多无关数据。
4. 核心信息优先展示，辅助信息适当弱化。
5. 复杂内容可通过筛选、图例、详情提示或切换机制组织。
6. 不得因为追求科技感而降低图表可读性。
7. 不强制所有区域具有相同高度和宽度。

---

## 七、图表设计与数据表达

### 7.1 图表基础风格

图表必须优先保证数据准确、信息可读和业务意义明确。

统一规范：
- 图表背景透明或使用与面板接近的深色。
- 网格线使用低对比度蓝灰色。
- 坐标轴不应过度突出。
- 图例位置保持合理。
- 数据系列颜色在同类图表中保持一致。
- 重点数据可以使用更亮的颜色。
- 只有确有需要时才使用渐变填充。
- 不使用厚重的图表边框。
- 不得为了科技感添加无意义的三维效果。

### 7.2 图表类型选择

根据数据关系选择图表，而不是为了统一视觉强行使用同一种图表。

适用原则：

- 时间变化：折线图、面积图。
- 类别比较：横向条形图、柱状图。
- 构成比例：环形图或堆叠图。
- 空间分布：地图或空间热力图。
- 实时监测：趋势图、状态列表或仪表。
- 排名比较：条形图或排名列表。
- 任务进度：进度条、阶段分布或趋势图。
- 多指标关系：散点图或其他适合的数据关系图。

图表选择必须基于真实数据的维度、单位和业务问题。

禁止：
- 将所有比例数据都做成环形图。
- 将所有指标都做成仪表盘。
- 用饼图比较大量类别。
- 用无法准确比较的面积或立体效果展示数值。
- 对不适合的数据强行使用地图。
- 使用不符合真实数据关系的双轴图表。

### 7.3 坐标轴与网格线

- 坐标文字建议使用 11–12px。
- 辅助网格线使用低对比度灰蓝色。
- 网格线不应比数据线更显眼。
- 坐标轴单位必须清楚。
- 时间轴刻度应根据时间跨度自动调整。
- 数值轴应合理选择刻度间隔。
- 对数轴或非零基线必须具有明确的业务理由。
- 数据量较大时，避免展示过密的刻度标签。
- 禁止坐标文字被面板边界截断。

### 7.4 数据系列配色

建立稳定的系列颜色表。

建议顺序：
1. 主要系列：科技蓝。
2. 第二系列：青色。
3. 重点系列：低饱和金色。
4. 第四系列：绿色。
5. 第五系列：紫色或其他经过对比度验证的辅助色。

使用规则：
- 同一个业务指标在不同图表中尽量保持颜色一致。
- 不得将金色随机分配给每一个系列。
- 重要数据突出显示，其他系列保持适度对比度。
- 多系列图表应配备清晰图例。
- 颜色不足以区分系列时，应同时采用线型、点形或标签辅助区分。
- 不得让所有系列都使用同样的亮度和视觉权重。

### 7.5 折线图

- 主线宽度建议为 2px。
- 次要系列可以使用 1.5px。
- 数据点默认适度弱化。
- 当前重点节点可以增加清晰标记。
- 面积填充应使用低透明度。
- 交互提示应展示准确数值、时间和单位。
- 不得持续闪烁整条曲线。
- 不得为每个数据点都添加永久标签。

### 7.6 柱状图与条形图

- 柱体宽度和间距保持稳定。
- 数据量较多时优先考虑横向条形图或滚动区域。
- 柱体使用实色或低强度渐变。
- 重点数据可以使用金色或亮蓝色。
- 不得给每根柱体都添加发光效果。
- 数值标签只在必要时展示。
- 类别较长时应使用合理的换行、截断或滚动策略。

### 7.7 环形图与比例图

- 中心数值必须与图表含义一致。
- 图例应清晰展示类别、数值或百分比。
- 扇区颜色应保持可区分。
- 小占比类别不应因为视觉装饰而消失。
- 不得通过立体效果误导比例判断。
- 当类别过多时，应优先考虑其他图表形式。

### 7.8 图表交互

根据项目需求支持：
- 鼠标悬停提示。
- 图例开关。
- 区域筛选。
- 时间范围选择。
- 数据点详情。
- 合理的缩放和漫游。

规则：
1. 交互提示框应使用深色背景、细边框和清晰文字。
2. 提示框必须展示准确数值与单位。
3. 不得遮挡关键数据点。
4. 交互不得影响大屏的稳定布局。
5. 实时刷新时应保留合理的图表状态。
6. 对于纯展示型大屏，不应添加没有实际用途的复杂交互。

## 八、地图、实时监测与动态指标

只有当业务确实涉及地理空间、实时监控或动态状态时，才启用相关设计。

### 8.1 地图

- 地图配色应与深色整体风格协调。
- 底图不得过亮。
- 道路、边界和区域轮廓应具有清晰层级。
- 关键位置使用科技蓝或金色进行有限强调。
- 异常点使用状态色。
- 地图图例和比例信息必须清晰。
- 不得让地图装饰压过数据点。
- 地图标注过密时，应采用聚合、分层或缩放策略。

地图数据、坐标和区域名称必须来自真实业务数据，不得生成虚构位置。

### 8.2 实时指标

实时数据需要具备稳定的更新机制。

规范：
- 清晰显示数据时间或更新时间。
- 重要异常可以有轻量状态提示。
- 不得让整个页面不断闪烁。
- 数字变化采用克制的过渡效果。
- 高更新频率的指标应避免频繁触发整个页面重绘。
- 接口失败时展示异常状态和最后有效数据的时间。
- 必须区分实时值、历史值、缓存值和估算值。
- 不得将旧数据伪装成最新数据。

### 8.3 动画

推荐动画时间：
- 轻量交互：120–180ms。
- 面板切换：180–240ms。
- 指标变化：根据刷新频率合理设置。

禁止：
- 无意义的无限旋转。
- 全屏扫描光效。
- 所有数字持续滚动。
- 整个面板持续呼吸发光。
- 每次数据更新都重新播放完整入场动画。

应尊重减少动态效果的系统偏好，保证长时间观看的舒适性。

---

## 九、标题、标注与图例

### 9.1 面板标题

- 字号建议为 16–20px。
- 字重 600。
- 颜色使用主要文字色。
- 可在标题旁增加短蓝线或小型强调标记。
- 不要为每个标题使用独立装饰风格。
- 标题必须能准确表达面板内容。
- 必要时显示统计口径、时间范围或单位说明。

### 9.2 数据标注

- 重点标注优先于普通标注。
- 标注文字建议使用 11–13px。
- 数值和单位应合理分组。
- 避免多个标签互相重叠。
- 标签颜色必须与背景保持足够对比度。
- 不要给所有数据点都永久添加数值。
- 对重要峰值、异常值或关键节点，可使用适当强调。

### 9.3 图例

- 图例应靠近对应图表。
- 图例颜色与真实数据系列一致。
- 文本和标记之间保持适当间距。
- 系列较多时应支持合理换行或其他布局。
- 不得因为装饰而省略必要的图例说明。
- 图例开关应有清晰的交互反馈。

---

## 十、面板内部布局

面板的内部结构应根据内容灵活决定。

可选结构：
- 标题 + 核心数字。
- 标题 + 图表 + 图例。
- 标题 + 趋势图 + 辅助指标。
- 标题 + 排名列表。
- 标题 + 实时状态列表。
- 标题 + 地图 + 图例。
- 标题 + 多指标组合。
- 标题 + 数据表格。

以上仅是结构参考，不是固定模板。

执行规则：
1. 每个面板必须有明确的数据目的。
2. 标题、主要内容和辅助说明应有稳定层级。
3. 不得在没有业务价值时强行添加统计卡片。
4. 面板内容过多时，应重新组织信息而不是缩小所有文字。
5. 图表和指标之间应具有清晰的数据关系。
6. 不能为了填满面板而加入无关装饰。
7. 同一大屏的面板应保持一致的内边距和标题规范。
8. 允许重点区域与普通区域采用不同的尺寸和视觉权重。

---

## 十一、数据真实性与异常处理

数据大屏必须以真实数据为基础。

执行要求：
1. 优先复用现有接口、数据模型和业务逻辑。
2. 不得虚构统计数字、增长率、排名或地图坐标。
3. 不得为了视觉完整而用随机数据填充正式页面。
4. 无数据时展示明确的空状态。
5. 数据加载中时使用适度的加载指示。
6. 请求失败时显示明确的错误状态。
7. 缺失数据不得默认解释为零。
8. 百分比和汇总数据必须遵循真实的计算口径。
9. 时间范围和统计单位必须清晰。
10. 需要模拟数据进行开发时，必须明确标识为演示数据，并与正式接口逻辑隔离。

异常状态可以使用红色、橙色和辅助标记，但必须以实际业务状态为准。

## 十二、前端技术与代码实现约束

### 12.1 改造前分析

开始修改之前，先检查：
- 当前前端框架。
- 已使用的图表库。
- 现有页面和路由。
- 全局样式和主题配置。
- 数据请求方式。
- 实时数据刷新机制。
- 地图组件和地图数据来源。
- 全屏、缩放和屏幕适配逻辑。

不得未经分析直接更换整个技术栈。

### 12.2 设计 Token

优先通过 CSS Variables 或项目现有的主题系统管理颜色、间距、字体、面板边框和图表样式。

建议将以下内容集中管理：
- 背景与面板颜色。
- 金色与科技蓝强调色。
- 状态色。
- 字体层级。
- 面板内边距。
- 网格间距。
- 边框和圆角。
- 阴影和辉光。
- 动画时长。
- 图表系列颜色。

避免在多个组件中重复定义相同的颜色和尺寸。

### 12.3 布局实现

- 优先使用 CSS Grid 和 Flexbox。
- 避免大量绝对定位。
- 只对确实需要叠加的装饰层使用绝对定位。
- 不得使用固定宽高强行拼接所有面板。
- 图表容器必须具有有效尺寸。
- 面板变化后应触发图表尺寸适配。
- 全屏切换后应正确重绘图表。
- 防止图表初始化时容器高度为零。
- 防止动态数据更新导致布局抖动。

### 12.4 图表库

优先使用项目已经安装的图表库。

如果项目使用 ECharts：
- 建立统一的图表主题配置。
- 统一轴线、网格、图例、提示框和系列颜色。
- 通过统一配置生成图表，减少重复代码。
- 根据数据类型设置合适的图表选项。
- 正确处理组件卸载、事件清理和实例销毁。
- 避免频繁重新初始化整个图表实例。
- 数据更新优先使用适合现有架构的增量更新方式。
- 图表配置必须基于真实数据结构。

不得在没有必要时同时引入多个图表库。

### 12.5 工程约束

- 保留现有路由和业务模块。
- 保留真实接口及其请求参数。
- 保留现有 DTO、VO 和响应结构。
- 保留已有权限逻辑。
- 不得擅自修改后端业务规则。
- 不得用静态数据替换生产接口。
- 不得删除现有功能来简化页面。
- 优先抽取可复用的面板标题、统计指标、图表容器和图例组件。
- 不得为了视觉效果将所有代码堆积在一个巨大组件中。

## 十三、执行流程

### 第一步：分析项目

识别当前技术栈、业务数据、页面结构、图表库、数据来源和目标屏幕尺寸。

先理解实际业务，再决定视觉布局。

### 第二步：建立主题系统

统一背景、面板、边框、字体、金色、科技蓝、状态色和图表系列颜色。

### 第三步：建立布局体系

根据数据优先级和实际屏幕比例安排区域。

不预设面板数量，不强制三列布局，不为凑满空间添加无意义内容。

### 第四步：统一面板和图表

建立统一的面板标题、边框、图例、坐标轴、提示框、数据标签和核心数字规范。

### 第五步：接入真实数据

复用项目现有接口和数据结构，保证数值、单位、时间、状态和统计口径准确。

### 第六步：完善交互

处理图表提示、筛选、时间范围、全屏、刷新、异常提示和必要的动态效果。

### 第七步：响应式验证

检查不同屏幕比例、窗口缩放、全屏切换、文字溢出和图表重绘。

### 第八步：完成验收

检查视觉一致性、数据真实性、图表可读性、控制台错误和页面运行情况。

最后说明实际修改的文件、完成的功能、执行过的验证和仍然存在的问题。

## 十四、最终验收标准

### 视觉质量

- [ ] 黑金与科技蓝分工明确。
- [ ] 背景足够深，但文字清晰可读。
- [ ] 金色只用于关键强调。
- [ ] 面板边框统一且不过度发光。
- [ ] 数字层级清晰，单位和说明完整。
- [ ] 图表配色稳定，坐标和图例易读。
- [ ] 重要数据突出，次要数据适度弱化。
- [ ] 面板数量和布局根据业务决定。
- [ ] 没有明显的装饰堆砌和无意义动画。

### 数据质量

- [ ] 指标来自真实数据或明确标识的演示数据。
- [ ] 单位、时间和统计口径正确。
- [ ] 缺失值和零值能够正确区分。
- [ ] 异常状态映射符合业务定义。
- [ ] 图表数据与指标数字保持一致。

### 工程质量

- [ ] 复用了现有技术栈。
- [ ] 统一设计 Token 已建立。
- [ ] 图表可以正确初始化、更新和销毁。
- [ ] 全屏和窗口变化后布局正常。
- [ ] 没有明显的文字重叠、图表裁切和面板溢出。
- [ ] 原有业务逻辑和接口没有被擅自修改。
- [ ] 实际测试结果得到如实记录。

## 最终设计原则

**用黑色建立空间，用科技蓝组织数据，用金色强调价值，用清晰的数字和图表表达业务。**

统一的是配色、字体、面板、图表、数字和动态效果；自由的是业务模块、面板数量、图表类型、区域比例和信息结构。

最终交付应是一套真正可复用、可维护、数据准确、适合长期运行的数据可视化界面，而不是只有静态装饰效果的科技风页面。
```
