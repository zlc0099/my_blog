这套规范用于日系视觉小说（Visual Novel / ADV）气质的前端页面：**天空场景 + 半透明毛玻璃 + 衬线字阶 + 角色对话 + 剧情选项 + 细腻反馈**。它统一的是场景、面板、字体、对话框、选项和状态；页面数量、模块数量、角色数量和选项数量由真实内容决定，不预设固定布局。

## 适合什么场景

- 清单、测试、问答、选择类产品，用户是在阅读和做选择，不是在填后台表单。
- 需要场景氛围和叙事感，但不能牺牲文字可读性和操作效率。
- 桌面和手机都要用，手机需要底部面板、纵向选项和安全区适配。

## 视觉方向

- 场景优先：天空、云层、夕阳、校园、窗边、远山等环境承担叙事。
- 内容优先：文字清晰可读，背景不能干扰阅读。
- 面板轻量：透明度、模糊、细边框和柔和阴影，不要厚重实体卡片。
- 排版有节奏：标题、正文、旁白、角色姓名和辅助信息有明确字阶。
- 交互有反馈：选项、对话推进、悬停、选中、禁用、加载都有视觉响应。
- 结构自适应：根据真实内容组织布局，不预先限定页面、模块或选项数量。

## 设计 Token

- 场景：天空 `#9CCCEB`，云 `#F5FAFF`，地平线 `#DDEAF4`。
- 文字：主 `#25364A`，次 `#607287`，弱 `#8B9AAA`，深色面板上的文字 `#F8FBFF`。
- 毛玻璃：底 `rgba(248,252,255,.76)`，边框 `rgba(255,255,255,.68)`，阴影 `0 12px 36px rgba(42,72,104,.12)`。
- 强调：`#648FC7`，hover `#507EB9`，浅底 `rgba(100,143,199,.14)`。
- 状态：成功 `#4D9A83`，警告 `#C99554`，危险 `#C96F79`，禁用 `#A7B3BF`。
- 圆角：8 / 14 / 20px；动效：160ms / 260ms。
- 天蓝用于天空和氛围，白与冷灰用于面板和辅助信息，蓝色用于交互和选中，暖橙只用于夕阳主题或少量强调，红色只用于错误和危险。深色夜景要切换暗色玻璃和文字，不要机械沿用浅色面板。

## 字体与字阶

- 叙事字体：`"Noto Serif SC", "Source Han Serif SC", "Songti SC", "SimSun", serif`。
- 界面字体：`"Inter", "PingFang SC", "Microsoft YaHei", sans-serif`。
- Display 40–64px，H1 32–44px，H2 24–32px，H3 18–24px，Body Large 17–20px，Body 14–16px，Caption 12–13px。
- 对话正文行高 1.8–2.0，普通正文 1.65–1.85；桌面可以更宽松，移动端适当缩小标题，但不要把文字压进过窄的列。
- 主标题、角色姓名、对话正文用衬线；按钮和操作提示可用无衬线；数字、时间、状态优先保证辨识度，不用难读的艺术字体。
- 长文本控制阅读宽度，不铺满超宽屏；逐字显示必须能直接显示完整文本，切换页面时清理动画状态，尊重减少动态效果偏好。

## 场景与构图

- 背景独立成层：场景图 → 色彩叠加 → 氛围（柔光、薄雾、暗角、缓慢云层）→ 内容层。
- 背景不能覆盖按钮、文字和键盘焦点；图片裁剪要保证主要视觉内容不被屏幕比例严重截断。
- 保留视觉焦点和呼吸空间，主内容不必占满全屏；对话框和背景主体之间保持距离。
- 超宽屏可以扩大场景，但不能无限拉伸正文；移动端优先阅读顺序和操作空间，不强行复刻桌面横向构图。
- 不预设页面必须有几个区块、对话框、选项、角色或卡片；每个模块都要有明确用途，禁止无意义装饰面板。
- 如果场景是深色夜景，玻璃面板、文字和状态色要切换为暗色版本。

## 毛玻璃面板

- 基础：`background: var(--adv-glass-bg); border: 1px solid var(--adv-glass-border); border-radius: 20px; box-shadow: 0 12px 36px rgba(42,72,104,.12); backdrop-filter: blur(18px) saturate(125%);`。
- 面板保留背景透视感，细边框，不用厚重描边；阴影用于分离前后景，不要形成悬浮卡片墙。
- 圆角统一，不要同一页出现大量不同圆角；文字区域可以提高不透明度，装饰区域可以更低。
- 面板不能过度模糊，背景完全消失就没有场景感；对比度不足时优先提高面板不透明度或调整叠加层，不要靠文字阴影硬撑。
- 不支持 `backdrop-filter` 时，面板仍要有足够不透明背景和清晰边界，可读性和按钮状态不能依赖模糊。

## 姓名铭牌与对话框

- 铭牌可包含姓名、可选身份/标签、细线或小面积强调、简短状态；不要求所有元素都有，没有姓名时不渲染空白铭牌。
- 铭牌要与对应对话框建立明确关联；姓名比辅助标签突出；可用衬线、适度字距或小面积主题色；不要做成厚重游戏 HUD、金属质感或复杂花纹。
- 多角色对话时，当前角色用强调色或更高对比，非当前角色降低强调；切换用短暂淡入或轻微位移；角色信息缺失要有合理默认，不出现空白或报错。
- 对话框位于画面下方或内容主体附近，半透明玻璃，包含姓名、对话正文、可选补充说明和继续/展开提示；内边距足够，长文自然换行或展开，不能被固定高度裁切。
- 逐字显示要支持“再次触发直接显示完整文本”，未显示完不能跳过重要信息；不需要剧情状态机时，不要为了风格强行实现复杂对话逻辑。

## 选项按钮

- 默认半透明浅色底、克制边框、清晰文字；hover 背景轻微提亮或加深；focus 有明确键盘轮廓；active 轻微位移或缩放；selected 用强调色、标记或清晰背景差异；disabled 降低对比且不可操作；loading 显示等待反馈并防重复。
- 选项要像故事里的选择，而不是后台操作按钮；2–3 个即可，数量按真实内容决定，不固定。
- 选项必须连接真实行为：切换章节、展开内容、提交选择、展示成功/失败/确认；不能只做视觉可点击。
- 键盘 Tab 可导航，焦点清晰；只有明确采用 ADV 操作模式时才加方向键、Enter、Esc 快捷操作，且不能和输入框或辅助技术冲突；不能只靠颜色区分选中。

## 状态、动效与装饰

- 状态：Default、Hover、Focus、Active、Selected、Disabled、Loading、Success、Error、Empty 都要有视觉反馈。
- 动效：普通 hover 120–180ms，面板/内容过渡 200–320ms，章节切换适度淡入淡出；云层动画缓慢低对比；不要持续闪烁、强缩放、频繁抖动或高频粒子；所有元素不要同时动画。
- 支持 `prefers-reduced-motion`，关闭或简化非必要动画。
- 图标用统一线性风格，尺寸和线宽一致，用于辅助不取代关键文字；装饰可用云朵轮廓、柔光、细线、轻微颗粒、章节序号、小时间/位置标记，但不能挤占正文。
- 避免霓虹描边、复杂 HUD、厚重金属面板、无意义数据装饰和重复发光。

## 响应式、可访问性与性能

- 桌面可用宽幅场景和电影感构图，对话框可在下方或按视觉焦点布局；平板收紧边距，避免人物/标题/对话重叠；移动端对话框可接近全宽底部面板，背景重新裁剪，选项纵向排列，处理安全区、软键盘、窄屏换行和横竖屏。
- 禁止横向溢出和过小点击区域；长文本不能被固定高度截断。
- 正文与面板对比度足够；所有交互元素有清晰焦点；按钮有明确文本或可访问名称；状态不能只靠颜色；图片有合适替代文本；装饰背景不干扰屏幕阅读器；动态内容避免频繁播报；不要禁用浏览器缩放。
- 背景图用合适尺寸和格式，大型图合理加载，非首屏懒加载；避免大面积高频模糊和复杂滤镜；动画优先 transform/opacity；不为简单反馈引入重型依赖；低性能设备核心内容仍流畅。

## 工程约束

- 先检查目录、页面、组件、路由、样式和依赖；复用现有组件和设计系统，不重写整个项目。
- 不擅自替换框架、构建工具、路由或状态管理；颜色、字体、间距、圆角、阴影、动效统一管理。
- 对话框、姓名铭牌、选项按钮和状态提示尽量复用；组件职责清晰，不把所有 UI 和交互堆进一个巨大组件；不用大量重复内联样式。
- 保留现有业务逻辑、接口、表单校验和权限；不删功能、路由、字段或模块；不为视觉效果虚构接口、数据或不存在的状态。
- 背景图优先用项目现有合法资源；不足时用可替换配置；不引用失效地址；图片失败有渐变或纯色兜底；场景图与主题协调。
- 处理 z-index 和层叠上下文；为玻璃面板提供不支持模糊时的降级；背景动画不能挡鼠标事件；全局事件监听要清理；组件卸载后停止定时器和动画；交互状态与实际业务状态一致；不用假加载动画替代真实请求。

## 验收

- 第一眼能感受到 ADV 的场景感和叙事感；天空、玻璃和文字协调。
- 标题、正文、姓名铭牌、辅助信息字阶清晰；选项有完整的默认/悬停/聚焦/选中/禁用状态。
- 加载、成功、失败、空状态有合理反馈；背景不干扰阅读；动画克制并支持减少动态。
- 桌面和移动端正常；设计统一但不把所有页面强制成同一布局；不固定页面、栏目、角色或选项数量。
- 不破坏原业务逻辑和工程结构；代码可维护，视觉效果与实际交互一致。

## 常用短句

- “背景负责情绪，文字负责内容，面板负责组织，按钮负责引导下一步。”
- “场景是场景，面板是面板，不要把背景做成一张普通卡片。”
- “毛玻璃要轻，文字对比度要够；模糊不能成为可读性的前提。”
- “选项必须连接真实行为，不能只是看起来能点。”

## 完整提示词

下面是这份规范的完整提示词，可以直接整段复制给 Agent。它包含嵌套的 CSS 代码块，外层用 4 个反引号包裹。

````prompt
# 前端 UI 设计提示词：视觉小说 ADV 排版风格

## 一、设计目标

你是一名资深前端设计师、视觉小说 UI 设计师与交互体验工程师。

请为当前项目设计并实现一套具有日系视觉小说（Visual Novel / ADV）气质的前端 UI。整体采用「天空场景 + 半透明毛玻璃界面 + 优雅衬线字阶 + 角色对话 + 剧情选项 + 细腻状态反馈」的设计方向。

设计应当像一部可以交互的视觉小说：背景负责建立情绪，文字负责传达内容，面板负责组织信息，按钮负责引导用户进入下一段内容。

不要将页面做成普通 SaaS 后台、常规卡片式官网、游戏 HUD 仪表盘或简单的图片加文字布局。应当强调画面构图、留白、文字节奏、前后景关系与沉浸式阅读体验。

### 核心原则

1. 场景优先：天空、云层、夕阳、校园、窗边、远山等环境承担视觉叙事。
2. 内容优先：文字清晰可读，背景不能干扰信息阅读。
3. 面板轻量：通过透明度、模糊、细边框和柔和阴影建立层次，避免厚重的实体卡片。
4. 排版有节奏：标题、正文、旁白、角色姓名和辅助信息具有明确的字阶。
5. 交互有反馈：选项、对话推进、悬停、选中、禁用和加载状态均需要视觉响应。
6. 结构自适应：根据项目真实内容组织布局，不预先限定页面数量、模块数量或选项数量。

---

## 二、整体视觉方向

### 2.1 场景氛围

使用具有叙事感的天空场景作为主要视觉语言。

推荐的背景方向：

- 晴朗的浅蓝天空与柔软白云。
- 午后阳光、校园窗景与远处树影。
- 日落时的粉橙色天空与暖色光线。
- 蓝紫色黄昏、薄雾、星空与安静的夜景。
- 具有空间纵深的街道、车站、屋顶或海边。

场景必须具有明确的视觉主体与空间层次。避免使用元素过多、对比过强、细节杂乱的背景图片。

优先采用高清背景图、渐变叠层、轻微暗角和低强度光影。背景可以随页面主题变化，但应保持统一的色彩倾向。

### 2.2 视觉关键词

`Visual Novel`、`Japanese ADV`、`Sky Background`、`Glassmorphism`、`Elegant Serif Typography`、`Dialogue Box`、`Character Nameplate`、`Narrative Choice`、`Soft Glow`、`Cinematic Composition`。

整体观感应当安静、轻盈、细腻、有故事感，同时具备现代网页的易用性。

---

## 三、设计 Token 与配色规范

建立统一的颜色变量，不要在各个组件中随意使用不同的颜色值。

建议定义以下 CSS 变量，并根据实际背景调整：

```css
:root {
  /* 场景色 */
  --adv-sky: #9CCCEB;
  --adv-cloud: #F5FAFF;
  --adv-horizon: #DDEAF4;

  /* 文字色 */
  --adv-text-primary: #25364A;
  --adv-text-secondary: #607287;
  --adv-text-muted: #8B9AAA;
  --adv-text-on-dark: #F8FBFF;

  /* 毛玻璃面板 */
  --adv-glass-bg: rgba(248, 252, 255, 0.76);
  --adv-glass-border: rgba(255, 255, 255, 0.68);
  --adv-glass-shadow: 0 12px 36px rgba(42, 72, 104, 0.12);

  /* 主题强调色 */
  --adv-accent: #648FC7;
  --adv-accent-hover: #507EB9;
  --adv-accent-soft: rgba(100, 143, 199, 0.14);

  /* 状态色 */
  --adv-success: #4D9A83;
  --adv-warning: #C99554;
  --adv-danger: #C96F79;
  --adv-disabled: #A7B3BF;

  /* 圆角与动效 */
  --adv-radius-sm: 8px;
  --adv-radius-md: 14px;
  --adv-radius-lg: 20px;

  --adv-transition-fast: 160ms ease;
  --adv-transition-normal: 260ms ease;
}
```

以上数值为初始参考，不是强制配色。实际实现时应根据场景背景、文字对比度和项目主题进行统一调整。

### 配色使用规则

- 天蓝色用于天空、主视觉和整体氛围。
- 白色与冷灰色用于面板、分隔线和次级信息。
- 蓝色用于可交互元素和当前选中状态。
- 暖橙色可用于夕阳主题、关键提示和少量视觉强调。
- 红色仅用于错误、危险或明确需要警示的状态。
- 禁止所有组件同时使用高饱和度颜色。
- 避免大面积纯白、不透明重面板、刺眼霓虹色和过强的发光效果。

如果场景背景为深色夜景，应切换为适配暗色背景的玻璃面板和文字颜色，而不是机械地沿用浅色面板。

## 四、字体与文字层级

### 4.1 字体选择

优先采用具有文学感、阅读感和日系视觉小说气质的衬线字体作为标题与叙事文字的主要字体。

推荐字体栈：

```css
:root {
  --font-narrative:
    "Noto Serif SC",
    "Source Han Serif SC",
    "Songti SC",
    "SimSun",
    serif;

  --font-interface:
    "Inter",
    "PingFang SC",
    "Microsoft YaHei",
    sans-serif;
}
```

使用原则：

- 页面主标题：衬线字体，具有鲜明的视觉性格。
- 角色姓名：衬线字体或具有辨识度的中等字重字体。
- 对话正文：易读的衬线字体，避免过细。
- 旁白与注释：降低字号和颜色对比度，但仍需保持可读性。
- 功能按钮与操作提示：可使用无衬线字体，提升识别效率。
- 数字、时间和状态信息：优先保证辨识度，不追求装饰效果。

不要为了模拟日系风格而随意使用难以阅读的艺术字体。

### 4.2 字阶体系

建立统一的响应式字体层级：

| 层级 | 建议字号 | 使用场景 |
|---|---:|---|
| Display | 40–64px | 首页主标题、章节标题 |
| H1 | 32–44px | 页面核心标题 |
| H2 | 24–32px | 章节或主要内容标题 |
| H3 | 18–24px | 内容分区标题 |
| Body Large | 17–20px | 主要对话、重要叙述 |
| Body | 14–16px | 普通正文、内容说明 |
| Caption | 12–13px | 辅助信息、时间、注释 |

桌面端可以使用较宽松的字距与行距；移动端需要适当缩小标题，并避免文字被压缩到过窄的列宽。

推荐对话正文行高为 `1.8–2.0`，普通正文行高为 `1.65–1.85`。

### 4.3 文字排版规则

- 每个文本区域应具有明确的主次关系。
- 标题与正文之间保留充足间距。
- 避免连续出现多个同等字号、同等字重的标题。
- 重要文本可以使用更深的颜色、更高的字重或适度的字号差异强调。
- 长文本应控制阅读宽度，不要铺满整个超宽屏幕。
- 对话文本可采用逐句呈现或轻量淡入，但必须提供完整内容的可访问方式。
- 中文标点、英文、数字混排时，应保持自然的字距和换行效果。

---

## 五、页面构图与布局规则

### 5.1 场景背景层

背景应当作为独立视觉层，而不是普通内容卡片。

推荐分层结构：

1. 背景图层：天空、云朵、校园、城市或其他场景。
2. 色彩叠加层：统一整体色调，保证文字对比度。
3. 氛围层：少量柔光、薄雾、暗角或缓慢移动的云层。
4. 内容层：标题、叙述、人物信息、对话框与交互控件。

使用清晰的层级管理背景和内容，避免背景动画覆盖按钮、文本或键盘焦点。

背景图片应采用合适的裁剪策略，确保主要视觉内容不会因屏幕比例变化而被严重截断。

### 5.2 画面留白

- 页面应保留明确的视觉焦点和呼吸空间。
- 主内容区不必占满整个屏幕。
- 重要信息可以偏左、居中或靠近画面下方，具体位置根据真实内容决定。
- 对话框和背景主体之间应保持足够的空间，避免互相遮挡。
- 超宽屏可以扩大场景范围，但不能无限拉伸正文。
- 移动端优先保证阅读顺序和操作空间，而不是强行复刻桌面端的横向构图。

### 5.3 不固定页面模块数量

不要预先规定页面必须包含多少个区块、对话框、选项、角色或内容卡片。

请根据现有项目的业务需求、信息层级和真实内容决定：

- 是否需要全屏场景。
- 是否需要人物立绘。
- 是否需要章节目录。
- 是否需要多选项交互。
- 是否需要额外的信息面板。
- 是否需要普通文章式内容区域。

每个模块都必须有明确用途。禁止为了表现视觉小说风格而重复添加无意义的装饰面板。

---

## 六、毛玻璃面板规范

毛玻璃面板是视觉小说 UI 的关键组件，应轻盈、半透明，并与背景保持融合。

### 6.1 基础样式

```css
.adv-glass-panel {
  background: var(--adv-glass-bg);
  border: 1px solid var(--adv-glass-border);
  border-radius: var(--adv-radius-lg);
  box-shadow: var(--adv-glass-shadow);
  backdrop-filter: blur(18px) saturate(125%);
  -webkit-backdrop-filter: blur(18px) saturate(125%);
}
```

### 6.2 使用规则

- 面板应保留一定的背景透视感。
- 采用细腻的半透明边框，而不是厚重描边。
- 阴影用于分离前后景，不应形成悬浮卡片墙。
- 圆角应统一，避免同一页面出现大量不一致的圆角值。
- 文字区域可以使用更高的不透明度，装饰区域可以使用更低的不透明度。
- 面板不能过度模糊，以免背景完全失去存在感。
- 对比度不足时，应优先提高面板不透明度或调整叠加层，而不是添加大量文字阴影。

### 6.3 兼容性要求

当浏览器不支持 `backdrop-filter` 时，面板仍然必须具备足够的不透明背景和清晰的边界。

不要让页面的可读性、按钮状态或主要功能依赖模糊效果才能成立。

---

## 七、角色姓名铭牌

姓名铭牌应具有明显的身份识别功能，同时保持精致、克制的视觉效果。

### 7.1 视觉结构

姓名铭牌可以包含：

- 角色姓名。
- 可选的身份或角色标签。
- 可选的细线、装饰符号或小型强调色。
- 可选的简短状态信息。

不要求每个铭牌都包含所有元素，应根据实际内容选择。

### 7.2 设计规范

- 铭牌应与对应的对话框建立明确的视觉关联。
- 可以使用半透明底色、细边框或轻微投影。
- 角色姓名应比辅助标签更突出。
- 可使用衬线字体、适度字距或小面积主题色。
- 不要将铭牌设计成厚重的游戏战斗 HUD。
- 不要使用过多金属质感、复杂花纹或高亮描边。
- 没有角色姓名时，不应渲染空白铭牌。

### 7.3 状态变化

如果项目包含角色切换或多角色对话，可以设计：

- 当前发言角色：强调色或较高文字对比度。
- 非当前角色：降低强调程度。
- 角色切换：短暂淡入或轻微位移动画。
- 角色信息缺失：使用合理的默认展示方式，而不是出现空白组件或报错。

---

## 八、ADV 对话框

### 8.1 视觉风格

对话框应具有经典视觉小说的叙事气质，同时符合现代网页的易读性。

推荐使用位于画面下方或内容主体附近的半透明玻璃面板，包含姓名铭牌、对话正文和可选的推进提示。

不要强制每个页面都采用全屏对话框。普通博客文章、项目介绍和学习笔记可以使用轻量叙述区域，只在适合的内容中使用 ADV 对话样式。

### 8.2 对话内容层级

建议按照以下优先级组织：

1. 角色姓名或叙述者标识。
2. 当前对话或正文内容。
3. 可选的补充说明。
4. 可选的继续、展开或下一步操作提示。

对话框应具有足够的内边距。文字过长时应自然换行或采用合适的展开方式，不能被固定高度裁切。

### 8.3 文字呈现

如果实现逐字显示效果：

- 支持逐字显示与直接显示完整文本两种状态。
- 用户再次触发时，可以直接显示当前完整文本。
- 内容未显示完毕时，不得意外跳过重要信息。
- 用户切换页面或章节时，应正确清理旧的动画状态。
- 必须考虑减少动态效果的系统偏好。
- 不得通过过慢的逐字动画阻碍用户阅读。

如果项目不需要剧情推进逻辑，则不必为了风格强行实现复杂的对话状态机。

---

## 九、选项按钮与交互选项

选项按钮是视觉小说与普通内容页面的重要区别之一。

### 9.1 基础视觉

选项按钮建议采用轻量的半透明底色、细边框、清晰的文字层级与适度圆角。

按钮应像故事中的选择，而不是普通的后台操作按钮。

推荐的视觉方向：

- 默认状态：半透明浅色底，边框克制。
- 悬停状态：背景轻微提亮或加深，边框更清晰。
- 聚焦状态：具有明确的键盘焦点轮廓。
- 按下状态：轻微位移或缩放反馈。
- 选中状态：强调色、标记符号或清晰的背景差异。
- 禁用状态：降低对比度，并阻止无效操作。
- 加载状态：显示简洁的等待反馈，避免重复提交。

### 9.2 交互行为

如果选项会触发真实业务操作，应确保按钮与业务逻辑正确连接。

例如：

- 选择后切换到对应章节。
- 点击后展开相关内容。
- 选择后展示明确的成功、失败或确认反馈。
- 无效操作时给出合理说明。
- 不可用选项应有清晰的禁用状态。
- 对有副作用的操作，应在必要时加入确认步骤。

不要仅制作视觉上可点击的按钮，却不实现对应行为。

如果项目只是静态展示页，则选项可以用于导航、锚点跳转或内容展开，不需要虚构复杂的剧情系统。

### 9.3 键盘操作

- 可交互选项应支持键盘 Tab 导航。
- 焦点样式必须清晰可见。
- 只有在页面明确采用 ADV 操作模式时，才添加方向键选择、Enter 确认或 Esc 返回等快捷操作。
- 快捷键不能与输入框、浏览器默认行为或辅助技术发生冲突。
- 不得仅依赖颜色区分选中状态。

---

## 十、状态反馈与微交互

所有交互元素都应具有完整的状态设计，而不是只有默认状态和悬停状态。

### 10.1 必须考虑的状态

| 状态 | 视觉反馈 |
|---|---|
| Default | 清晰、轻量、融入场景 |
| Hover | 背景、边框或阴影发生微小变化 |
| Focus | 明确的键盘焦点轮廓 |
| Active | 轻微位移或背景变化 |
| Selected | 持续可辨识的选中样式 |
| Disabled | 降低对比度且不可操作 |
| Loading | 显示加载提示并防止重复提交 |
| Success | 使用适度强调色和明确说明 |
| Error | 清晰提示问题，并提供合理的恢复方式 |
| Empty | 提供符合当前语境的空状态说明 |

### 10.2 动效规范

- 普通悬停反馈：约 120–180ms。
- 面板或内容过渡：约 200–320ms。
- 章节切换：根据内容重量选择适度的淡入、淡出或轻微位移。
- 背景云层动画：缓慢、低对比度，不得影响正文阅读。
- 避免持续闪烁、强烈缩放、频繁抖动或高频粒子效果。
- 不要给所有元素同时添加动画。

应支持 `prefers-reduced-motion`。当用户偏好减少动态效果时，关闭或简化非必要动画。

---

## 十一、图标、装饰与视觉细节

### 图标规范

- 优先采用统一的线性图标。
- 图标尺寸、线宽和视觉重量应保持一致。
- 图标用于辅助理解，不应取代关键文字。
- 不要同时混用大量风格不同的图标库。
- 装饰性图标应适量使用。

### 装饰元素

允许适度使用：

- 云朵轮廓。
- 柔和光斑。
- 细线分隔符。
- 微弱颗粒质感。
- 章节序号。
- 小型时间或位置标记。
- 轻量的装饰性符号。

这些元素必须服务于场景氛围与信息层级，不得挤占正文空间。

避免大面积霓虹描边、复杂 HUD、厚重金属面板、无意义的数据装饰和重复的发光元素。

---

## 十二、响应式布局

### 桌面端

- 允许使用宽幅场景图与更具电影感的构图。
- 对话框可位于画面下方，或根据视觉焦点灵活布局。
- 主标题可以具有更强的视觉存在感。
- 正文仍应控制阅读宽度。
- 不要为了填满屏幕而添加没有内容价值的面板。

### 平板端

- 适当收紧内容边距。
- 避免人物、标题和对话框发生重叠。
- 选项按钮应保留足够的点击面积。

### 移动端

- 优先保证正文阅读、按钮点击和导航操作。
- 对话框可以变为接近全宽的底部面板。
- 背景图片需要重新裁剪，不可简单缩小桌面端画面。
- 姓名铭牌与对话正文应保持明确层级。
- 选项可以纵向排列，并保留足够的间距。
- 长文本不得被固定高度截断。
- 处理好安全区域、软键盘、窄屏换行和横竖屏切换。
- 禁止出现横向溢出和过小的点击区域。

---

## 十三、可访问性与性能要求

### 可访问性

- 普通正文与面板背景之间应保持足够的对比度。
- 所有交互元素应具有清晰的键盘焦点。
- 按钮必须具有明确的文本或可访问名称。
- 状态变化不能仅依赖颜色表达。
- 图片应根据实际用途提供适当的替代文本。
- 装饰性背景不应干扰屏幕阅读器。
- 动态内容变化应避免不必要的频繁播报。
- 不得禁用浏览器正常的缩放与辅助功能。

### 性能

- 优先使用适当尺寸与格式的背景图片。
- 对大型背景图使用合理的加载策略。
- 对非首屏图片进行延迟加载。
- 避免大面积高频模糊和复杂滤镜造成性能下降。
- 动画优先使用合适的 transform 与 opacity。
- 不要为简单的视觉反馈引入不必要的重型依赖。
- 在低性能设备上保证核心内容与操作仍然流畅。

---

## 十四、前端工程实现约束

请在当前项目既有技术栈和工程结构内实现上述设计。

### 基本要求

1. 开始前先检查项目目录、现有页面、组件、路由、样式体系和依赖。
2. 优先复用现有组件和设计系统，不要为了视觉改造重写整个项目。
3. 不擅自替换框架、构建工具、路由系统或状态管理方案。
4. 将颜色、字体、间距、圆角、阴影和动效统一管理。
5. 对话框、姓名铭牌、选项按钮和状态提示应尽可能复用。
6. 保持组件职责清晰，避免把所有 UI 和交互逻辑堆进单个超大组件。
7. 不要使用大量重复的内联样式代替统一的设计规范。
8. 保持现有业务逻辑、数据接口、表单验证和权限规则不变。
9. 不要擅自删除现有功能、路由、数据字段或业务模块。
10. 不要为实现视觉效果而虚构后端接口、业务数据或不存在的状态。

### 背景图片要求

- 优先使用项目现有的合法图片资源。
- 如果现有资源不足，应采用可替换的资源配置方式。
- 不要引用失效图片地址。
- 不要让页面依赖未经验证的外部图片才能正常运行。
- 图片加载失败时应有合理的渐变或纯色背景兜底。
- 场景图与页面主题应保持协调。

### 技术细节

- 正确处理 z-index 与层叠上下文。
- 为玻璃面板提供不支持模糊效果时的降级样式。
- 避免背景动画阻挡鼠标事件。
- 避免使用全局事件监听却不进行清理。
- 避免组件卸载后继续执行定时器或动画回调。
- 避免交互状态与实际业务状态不一致。
- 不得以伪造的加载动画替代真实请求状态。
- 保持代码可维护、可扩展，并符合项目已有规范。

## 十五、执行步骤

请按照以下顺序完成设计与开发：

### 第一步：分析现有项目

识别当前项目类型、技术栈、页面结构、路由关系、业务功能、现有组件和资源。

明确哪些部分需要视觉改造，哪些部分必须保持不变。

### 第二步：建立视觉规范

先统一：

- 颜色 Token。
- 字体栈与字阶。
- 间距与圆角。
- 毛玻璃面板。
- 姓名铭牌。
- 对话框。
- 选项按钮。
- 状态反馈。
- 动效与响应式规则。

### 第三步：改造实际页面

结合项目的真实内容选择合适的 ADV 视觉表现形式。

可以采用场景式首页、轻量叙事内容区、章节导航、角色对话或选择式交互，但不要机械地把所有页面改成同一种布局。

### 第四步：实现交互

逐一检查按钮、链接、选项、导航、表单、加载、空状态、错误状态与成功反馈。

所有可交互元素都必须有合理的行为，不能只有外观。

### 第五步：检查与修复

检查：

- 页面是否保持统一的视觉风格。
- 背景与文字是否存在对比度问题。
- 毛玻璃面板是否过重或过透明。
- 标题、正文和辅助信息是否具有清晰层级。
- 选项按钮是否具有完整状态。
- 桌面端与移动端是否布局正常。
- 图片是否加载成功。
- 是否存在控制台错误、样式冲突和横向溢出。
- 现有业务功能是否仍然正常。

### 第六步：交付说明

完成后简要说明：

- 修改了哪些页面和组件。
- 新增或复用了哪些视觉规范。
- 实现了哪些交互。
- 哪些资源仍需要替换。
- 是否发现尚未解决的问题。

## 十六、最终验收标准

完成的 UI 必须满足以下条件：

- 第一眼能够感受到视觉小说 ADV 的场景感与叙事感。
- 天空背景、毛玻璃面板和文字排版相互协调。
- 标题、正文、姓名铭牌和辅助信息具有明确的字阶。
- 选项按钮具备完整的默认、悬停、聚焦、选中和禁用状态。
- 加载、成功、失败和空状态均有合理反馈。
- 背景不会妨碍正文阅读。
- 动画克制，支持减少动态效果。
- 桌面端与移动端均可正常使用。
- 设计规范统一，但不会把所有页面强制变成相同布局。
- 不固定页面数量、栏目数量、角色数量或选项数量。
- 不破坏原有业务逻辑和工程结构。
- 代码具备可维护性，视觉效果与实际交互一致。
````
