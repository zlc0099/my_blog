这套规范用于生产型深色侧栏中后台：**深色导航框架 + 浅色业务工作区 + 高密度信息 + 克制的组件装饰**。它统一的是导航锚点、颜色、字体、间距、控件尺寸、表格密度、状态表达和交互反馈；允许变化的是业务栏目、页面布局、字段数量和操作流程。

## 适合什么场景

- 企业级业务管理、政务信息化、工单/巡查/运维/审批/任务管理。
- 数据管理、运营管理和内部生产工具。
- 高频操作、大量表格、复杂表单，用户会长时间使用。

不适合炫酷数据大屏、赛博霓虹、营销页，也不适合过度卡片化的 SaaS 模板。

## 深色导航 Token

- 侧栏底 `#17212F`，品牌区/底部 `#111A26`，hover `#243246`，当前项 `#263C56`。
- 普通文字 `#B7C3D0`，hover/当前 `#FFFFFF`，图标 `#94A3B8`。
- 分隔线 `#2A3647`，当前项强调 `#4C9AFF`。
- 低饱和深蓝灰，不用纯黑铺满；普通菜单文字必须有足够对比度。

## 浅色工作区 Token

- 主色 `#2563EB`，hover `#1D4ED8`，active `#1E40AF`，浅底 `#EFF6FF`，边框 `#BFDBFE`。
- 页面底 `#F4F6F9`，表面 `#FFFFFF`，次级表面 `#F8FAFC`，hover `#F1F5F9`。
- 主文字 `#1F2937`，次要 `#475569`，辅助 `#64748B`，禁用 `#94A3B8`。
- 边框 `#E2E8F0`，细分隔 `#EDF0F4`，焦点环 `#93C5FD`。
- 成功 `#15803D / #F0FDF4 / #BBF7D0`；处理中 `#1D4ED8 / #EFF6FF / #BFDBFE`；待处理 `#B45309 / #FFFBEB / #FDE68A`；异常 `#B91C1C / #FEF2F2 / #FECACA`；中性 `#475569 / #F1F5F9 / #E2E8F0`。
- 状态映射必须先读项目已有的枚举、状态字典和接口，不要按中文名称猜；状态标签必须保留文字。

## 字体、间距与圆角

- 系统字体栈：`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`。
- 页面标题 22/600/30，区块标题 16/600/24，卡片标题 14/600/22，正文 14/400/22，控件 14/400/20，表格 13/400/20，辅助 12/400/18，关键数字 26/600/34。
- 表格用 13px 换密度，表单和按钮保持 14px；不要把所有文字统一缩到 12px。
- 4px 基础、8px 递增：页面左右 20–24，标题与主体 16–20，工具栏与表格 12–16，表单字段 16–20，弹窗/抽屉 20–24。
- 圆角：标签 4px，输入/按钮 5px，卡片 6px，弹窗 8px，胶囊 999px 只在必要时。
- 普通卡片不加阴影；表格靠边框；浮层阴影 `0 8px 24px rgba(15,23,42,.10)`；侧栏不用投影。

## 应用外壳

- 固定侧栏 + 顶部栏 + 可滚动工作区；侧栏展开 224px、收起 64px、顶栏 56px、主体左右 24px、顶部 20px。
- 侧栏固定，页面滚动不跟随；菜单过长只滚菜单；品牌区稳定；展开收起不引起主体大幅错位。
- 一级菜单 40px、二级 36px、间距 2–4px、左右 12px、图标 16–18px、图文间距 10px。
- 默认透明 + 次级文字；hover 深色背景；active 低饱和蓝底 + 白字 + 可选 3px 左强调线；展开动画 150–200ms。
- 收起只留图标居中，当前项仍可识别，hover 有提示，子菜单用浮层；不要文字截断后仍占位。
- 顶部栏白色 56px + 细线，可放折叠、面包屑、搜索、通知、用户菜单，按项目实际取舍；不要重复页面标题。

## 页面工作区

- 页面标题左对齐、主要操作右对齐；标题 22/600，辅助 12–13；标题区不要占太多垂直空间。
- 四层结构：页面底、业务容器、表格/表单/详情、弹窗/抽屉/菜单；靠间距、边界和背景分层。
- 不要每个字段都包成卡片，不要把所有页面做成卡片宫格。
- 主体独立滚动，侧栏和顶栏稳定；避免多个混乱滚动条；抽屉内部独立滚动；不要用固定高度藏内容。

## 生产级表格

- 密度：紧凑 36/36/12px/8/6，默认 40/44/13px/12/10，宽松 44/52/14px/16/14（表头高/行高/字号/水平内边距/垂直内边距）。默认 44px 行高。
- 表头浅灰白、左对齐、字重 500；排序列有明确反馈；固定表头要对齐。
- 行默认白、hover 浅灰蓝、选中低饱和浅蓝、禁用弱化；轻分割线，不重网格；默认不斑马纹；操作不撑高行；多选显示数量。
- 列宽按内容；长文本占剩余空间；数字/金额按语义对齐；操作列稳定；固定列处理遮挡；不要所有列等宽。
- 操作列：常用 1–2 个直接展示，次要进更多菜单，危险操作用危险色 + 确认；不要堆实心按钮；无权限按真实权限。
- 工具栏/查询：按使用频率排，常用首行，次要可展开；查询/重置主次明确；创建/导出合理分组；不要占太多高度。
- 分页稳定，显示总数、页码、每页条数、跳转；12–13px；不改后端分页参数；筛选变化按业务重置页码；空数据有明确空状态。

## 状态标签

- 12px、约 22px 高、水平内边距 8px、圆角 4px、浅底深字 + 可选浅边框。
- 同一业务状态在列表、详情、弹窗、统计中保持一致；不能只靠颜色区分，必须保留文字。
- 绿/蓝/橙/红/灰只是视觉分类，不是业务定义；先读枚举、常量、字典和接口，建立真实映射。
- 不要猜状态含义、不要强行统一不同模块、不要改后端状态值、不要用红色展示普通提示、不要用绿色掩盖未完成任务。
- 状态标签与操作语义一致：已完成不显示普通执行入口，已关闭不显示进行中样式，驳回保留真实状态；具体以权限和状态机为准。

## 抽屉与表单

- 抽屉宽度：轻量详情 420–480，常规表单 560–640，复杂表单 720–840；按字段数量决定，不强制统一。
- 结构：固定顶部 56px 标题区 + 可滚动内容区 + 固定底部操作区；标题左、关闭右、细分隔；内容 20–24px，字段 16–20px。
- 底部主操作靠右，取消等次要在前，危险操作单独区分；打开时背景稳定，只内容滚动，底部不遮最后一个字段。
- 关闭遵循原有数据保留规则；未保存修改按业务提示；提交防重复；校验错误清晰；成功后按原逻辑关闭或保留；避免闪动；关闭后恢复焦点。
- 表单优先单列；双列只在字段短、关联强、抽屉够宽时使用；标签与控件 6–8px，字段 16–20px，分组间 24–32px；长文本占满宽度。
- 控件高度 32/36/40；输入、选择、日期统一；聚焦主色边框；错误清晰；禁用与只读区分；必填统一；placeholder 不能代替标签。
- 分组只在字段有业务关联时用，标题 14/600；不要每组都包卡片；字段顺序按原业务流程；不得增删改字段。
- 校验错误贴近字段；红色边框 + 说明；提交防重复；失败保留输入；成功反馈；取消按原行为；副作用二次确认；不改原有校验规则和字段类型。

## 按钮与操作反馈

- 高度：默认 32、紧凑 28、宽松 36、大 40；圆角 5px。
- Primary 主提交/创建/确认，Default 取消/重置/辅助，Text 详情/查看，Danger 删除/撤销，Disabled 不可执行。
- 一个区域一个主按钮；次要操作不用实心主色；表格操作用文字或轻量按钮；不要堆彩色按钮。
- 危险色只在有业务含义时出现；禁用要有明确不可执行状态；加载防重复提交。
- 成功、失败、加载、空、无权限、网络异常、校验失败、危险确认统一处理；沿用现有消息组件，不引入多套提示系统。

## 响应式与工程约束

- 桌面优先；窄窗收起侧栏；表格优先合理列宽和横向滚动；抽屉不超视口；双列表单空间不足变单列；按钮组合理换行。
- 不通过缩小字体和控件来适配；弹窗不超屏、按钮不被遮挡；移动端不强行重做，但基础可用。
- 改造前检查框架、组件库、路由、主题、公共布局、表格/表单/弹窗/抽屉、权限和 API；不要另起一套 UI 框架。
- Token 放现有主题或全局样式，统一导航色、主色/状态色、字体、间距、控件高度、圆角、边框、阴影、层级和动画时间。
- 复用主布局、侧栏、顶栏、页面标题、查询工具栏、表格、状态标签、表单、抽屉/弹窗、分页、空/加载状态。
- 不重复写同一套样式、不重写成熟组件、不散落硬编码颜色、不用全局高优先级 CSS 强行覆盖、不破坏其他页面、不删原有功能。
- 保留技术栈、接口、DTO/VO、请求参数与响应、权限、状态枚举、路由菜单、分页和筛选；不用假数据替代真实接口；不擅自重构后端；改公共组件查所有调用方。

## 验收

- 视觉：深色侧栏与浅色工作区层级明确；展开/收起/悬停/选中统一；字阶清晰；留白、间距、控件高度一致；表格密度适合高频；状态颜色/文字/语义一致；抽屉三段清晰；圆角/边框/阴影克制；不靠渐变、发光和装饰卡片。
- 功能：路由和菜单正常；当前菜单选中正确；查询、重置、分页正常；表单校验和提交正常；抽屉开合/滚动正常；加载、成功、失败、空状态正常；权限和危险操作不变；接口参数/响应未改；无样式冲突、横向溢出和遮挡。

## 常用短句

- “深色侧栏是锚点，工作区保持浅色，不要全站做暗。”
- “先读状态枚举再配色，不要按中文猜业务状态。”
- “表格默认 44px 行高，操作列稳定，别让按钮撑高行。”
- “抽屉固定标题和底部操作，中间内容独立滚动。”

## 完整提示词

下面是这份规范的完整提示词，可以直接整段复制给 Agent。它只定义视觉基础和组件表现，不定义固定页面模板。

````prompt
# 前端 UI 提示词：深色侧栏生产级中后台设计规范

## 一、设计角色与总体目标

你是一名资深 B 端产品设计师、UI 设计系统工程师和前端开发工程师。

请基于当前项目，建立一套适用于生产环境的深色侧栏中后台 UI 设计体系。

设计定位：
- 企业级业务管理系统。
- 政务信息化平台。
- 工单、巡查、运维、审批和任务管理系统。
- 数据管理、运营管理和内部生产工具。
- 具有高频操作、大量表格和复杂表单的业务后台。

核心视觉方向：

**深色导航框架 + 浅色业务工作区 + 高密度信息布局 + 克制的组件装饰。**

设计关键词：
- 专业、稳定、严谨、清晰。
- 高信息密度、低视觉噪声。
- 导航层级明确、操作入口可预测。
- 状态清晰、数据易读、表单高效。
- 以功能效率为中心，不追求营销式视觉效果。

禁止设计成：
- 炫酷数据大屏。
- 赛博朋克或霓虹科技风。
- 大面积渐变和发光边框。
- 过度卡片化的 SaaS 模板。
- 过度圆润、充满胶囊按钮的消费级产品。
- 每个区域都使用阴影和独立容器的拼贴式布局。

设计的最终目标不是让后台看起来华丽，而是让用户在长时间工作、大量查看数据和频繁操作的情况下，依然能够快速定位、准确判断和高效完成任务。

## 二、全局设计 Token

必须先建立统一的设计 Token，再使用 Token 构建组件。不得在各个页面随意定义相近但不一致的颜色、间距、圆角和尺寸。

### 2.1 色彩系统

#### 深色导航色系

| Token | 色值 | 使用场景 |
|---|---|---|
| `--sidebar-bg` | `#17212F` | 侧栏基础背景 |
| `--sidebar-bg-deep` | `#111A26` | 品牌区或底部区域 |
| `--sidebar-bg-hover` | `#243246` | 导航悬停背景 |
| `--sidebar-bg-active` | `#263C56` | 当前菜单背景 |
| `--sidebar-text` | `#B7C3D0` | 普通菜单文字 |
| `--sidebar-text-hover` | `#FFFFFF` | 悬停菜单文字 |
| `--sidebar-text-active` | `#FFFFFF` | 当前菜单文字 |
| `--sidebar-icon` | `#94A3B8` | 普通菜单图标 |
| `--sidebar-border` | `#2A3647` | 侧栏分隔线 |
| `--sidebar-accent` | `#4C9AFF` | 当前菜单强调标识 |

深色侧栏必须以低饱和深蓝灰为主，不使用纯黑色作为所有区域的背景。

菜单文字必须具备足够的对比度。不要为了营造暗色效果，将普通菜单文字设置成难以辨认的深灰色。

#### 主工作区色系

| Token | 色值 | 使用场景 |
|---|---|---|
| `--color-primary` | `#2563EB` | 主按钮、链接、焦点 |
| `--color-primary-hover` | `#1D4ED8` | 主色悬停 |
| `--color-primary-active` | `#1E40AF` | 主色按下 |
| `--color-primary-light` | `#EFF6FF` | 选中辅助背景 |
| `--color-primary-border` | `#BFDBFE` | 主色相关边框 |
| `--page-bg` | `#F4F6F9` | 页面工作区背景 |
| `--surface` | `#FFFFFF` | 表格、表单、弹窗等表面 |
| `--surface-muted` | `#F8FAFC` | 次级内容区、表头 |
| `--surface-hover` | `#F1F5F9` | 表格行等悬停背景 |
| `--text-primary` | `#1F2937` | 标题、正文 |
| `--text-secondary` | `#475569` | 次级信息 |
| `--text-muted` | `#64748B` | 辅助说明 |
| `--text-disabled` | `#94A3B8` | 禁用文字 |
| `--border-default` | `#E2E8F0` | 默认边框 |
| `--border-subtle` | `#EDF0F4` | 轻量分隔线 |
| `--focus-ring` | `#93C5FD` | 键盘焦点提示 |

#### 状态色

| 状态 | 前景色 | 浅背景色 | 边框色 |
|---|---|---|---|
| 成功 | `#15803D` | `#F0FDF4` | `#BBF7D0` |
| 处理中 | `#1D4ED8` | `#EFF6FF` | `#BFDBFE` |
| 待处理 | `#B45309` | `#FFFBEB` | `#FDE68A` |
| 异常 | `#B91C1C` | `#FEF2F2` | `#FECACA` |
| 中性 | `#475569` | `#F1F5F9` | `#E2E8F0` |

状态色必须具有明确的业务语义。

不得将所有待处理状态都自动标记为黄色，也不得擅自推断项目中状态的含义。必须先读取已有业务枚举、状态字典和接口返回值，再进行映射。

状态标签除了颜色，还必须保留可识别的文字。

### 2.2 字体系统

默认字体栈：

`-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif`

统一字阶：

| Token | 字号 | 字重 | 行高 | 场景 |
|---|---:|---:|---:|---|
| `--font-page-title` | 22px | 600 | 30px | 页面标题 |
| `--font-section-title` | 16px | 600 | 24px | 区块标题 |
| `--font-card-title` | 14px | 600 | 22px | 卡片标题 |
| `--font-body` | 14px | 400 | 22px | 常规正文 |
| `--font-control` | 14px | 400 | 20px | 表单和按钮 |
| `--font-table` | 13px | 400 | 20px | 高密度表格 |
| `--font-caption` | 12px | 400 | 18px | 辅助说明 |
| `--font-metric` | 26px | 600 | 34px | 关键统计数字 |

规则：
1. 页面标题必须清晰，但不得占用过多垂直空间。
2. 表格默认使用 13px 字体，以兼顾数据密度和可读性。
3. 表单正文、按钮和常规操作文字仍使用 14px。
4. 不得为了追求紧凑而将所有文字统一缩小至 12px。
5. 同一层级的标题必须保持统一的字号和字重。
6. 时间、编号、金额等数据应保持稳定的对齐方式。
7. 允许为数字使用等宽数字特性，例如 `font-variant-numeric: tabular-nums`。

### 2.3 间距系统

采用 4px 基础间距，主要以 8px 递增。

| Token | 数值 | 使用场景 |
|---|---:|---|
| `--space-1` | 4px | 图标与文字的微间距 |
| `--space-2` | 8px | 紧邻元素 |
| `--space-3` | 12px | 控件内部和操作组 |
| `--space-4` | 16px | 默认组件间距 |
| `--space-5` | 20px | 中等区块间距 |
| `--space-6` | 24px | 页面主要区块间距 |
| `--space-8` | 32px | 大型区域分隔 |

执行要求：
- 页面主体左右留白通常为 20–24px。
- 页面标题与主体内容之间保持 16–20px。
- 表格工具栏与表格之间保持 12–16px。
- 表单字段之间保持 16–20px。
- 弹窗和抽屉内部默认使用 20–24px。
- 紧密关联的字段和操作应缩短间距。
- 无关内容区块之间必须留出明确的视觉间隔。
- 禁止为所有元素机械地套用同一个间距。

### 2.4 圆角与阴影

采用克制、偏硬朗的企业级风格。

| Token | 数值 | 场景 |
|---|---|---|
| `--radius-sm` | 4px | 状态标签、小控件 |
| `--radius-control` | 5px | 输入框、按钮 |
| `--radius-card` | 6px | 普通内容容器 |
| `--radius-dialog` | 8px | 弹窗、抽屉相关浮层 |
| `--radius-pill` | 999px | 仅限明确需要的圆点或胶囊 |

阴影规范：
- 普通卡片：默认不加阴影。
- 表格容器：优先使用边框，不使用悬浮阴影。
- 下拉菜单：使用轻量浮层阴影。
- 弹窗：使用适度阴影，与遮罩共同建立层级。
- 抽屉：仅在与页面交界处使用轻微阴影。
- 侧栏：通过颜色分区和边界线建立层级，不使用明显投影。

建议统一浮层阴影：

`0 8px 24px rgba(15, 23, 42, 0.10)`

禁止每个卡片、每个表格和每个页面区块都添加阴影。

## 三、应用外壳与侧栏锚点

### 3.1 整体布局

采用固定侧栏 + 顶部栏 + 可滚动工作区的应用外壳。

布局结构：

- 左侧：深色主导航。
- 顶部：浅色工具栏。
- 主体：浅灰色工作区。
- 页面内容：根据具体业务自由组合。
- 浮层：弹窗、抽屉、下拉菜单等。

推荐尺寸：
- 侧栏展开宽度：224px。
- 侧栏收起宽度：64px。
- 顶部栏高度：56px。
- 页面主体左右内边距：24px。
- 页面主体顶部内边距：20px。
- 主内容最小宽度应结合表格和表单实际需求决定，不强制所有页面固定宽度。

这些尺寸属于设计基准，可根据已有项目的实际布局适当调整。

### 3.2 侧栏锚点

侧栏的锚点是整个后台的稳定导航基准，必须在所有业务页面中保持一致。

规范：
1. 侧栏在桌面端保持固定位置。
2. 侧栏高度覆盖可用视口高度。
3. 页面主体滚动时，侧栏不跟随内容上下移动。
4. 菜单内容过长时，仅侧栏菜单区域滚动。
5. 品牌区域位于顶部，保持稳定。
6. 主导航区域位于品牌区域下方。
7. 底部固定区域可以容纳系统设置、帮助或用户相关入口，但仅在项目确实需要时显示。
8. 展开和收起时，不得引起主工作区大幅错位或内容闪动。
9. 页面切换时，侧栏当前位置、菜单状态和导航层级应保持合理。
10. 不得为不存在的业务模块虚构菜单。

### 3.3 导航菜单

菜单高度：
- 一级菜单：40px。
- 二级菜单：36px。
- 菜单之间的垂直间距：2–4px。
- 菜单左右内边距：12px。
- 图标尺寸：16–18px。
- 图标与文字间距：10px。

视觉状态：

默认状态：
- 背景透明。
- 文字采用次级导航色。
- 图标采用低饱和灰蓝色。

悬停状态：
- 使用深色悬停背景。
- 文字适度提亮。
- 不使用强烈发光效果。

激活状态：
- 使用低饱和蓝色背景。
- 文字和图标提高对比度。
- 可使用 3px 左侧强调线。
- 激活标识不得改变菜单文字的水平对齐关系。

展开状态：
- 使用统一的箭头图标。
- 子菜单缩进保持一致。
- 动画简洁，时长建议 150–200ms。

禁止：
- 每个菜单使用不同颜色。
- 使用大面积高亮蓝色覆盖整个侧栏。
- 一级和二级菜单没有明显层级差异。
- 当前路由对应的菜单无法自动激活。
- 页面刷新后菜单选中状态错误。
- 菜单展开导致主体区域宽度反复变化。

### 3.4 收起状态

侧栏收起时：
1. 仅保留必要图标。
2. 图标水平居中。
3. 当前菜单仍能通过背景或强调线识别。
4. 菜单图标必须保留明确的悬浮提示。
5. 子菜单可通过合理的浮层展开。
6. 不得出现文字截断后仍占据原有空间的情况。
7. 收起与展开应支持重复切换。
8. 切换过程中不得破坏页面滚动位置。

### 3.5 顶部工具栏

顶部栏高度固定为 56px，背景白色，底部使用轻量分隔线。

可包含：
- 侧栏折叠按钮。
- 面包屑导航。
- 页面辅助操作。
- 全局搜索入口。
- 通知入口。
- 用户菜单。

以上均为可选元素，必须根据项目已有功能决定是否展示。

规范：
- 不要把所有可能的工具按钮都塞进顶部栏。
- 面包屑应准确反映当前路由层级。
- 用户菜单应提供清晰的交互反馈。
- 顶部栏与主内容区保持稳定分界。
- 禁止重复显示当前页面标题和相同导航信息，造成视觉冗余。

## 四、页面工作区与信息组织

### 4.1 页面标题区域

推荐结构：
- 主标题。
- 可选的辅助说明。
- 可选的面包屑。
- 与当前业务相关的主要操作。

布局规则：
1. 标题左对齐，主要操作右对齐。
2. 主标题默认使用 22px 字号和 600 字重。
3. 辅助说明使用 12–13px 次级文字。
4. 页面标题区域不得占据过多垂直空间。
5. 不强制所有页面都展示副标题。
6. 主要操作必须根据业务重要性排序。
7. 标题区的结构可以因页面类型而变化，但视觉规范应一致。

### 4.2 工作区分层

使用以下层级组织信息：

第一层：页面背景。

第二层：业务内容容器。

第三层：表格、表单、详情区等具体工作区域。

第四层：弹窗、抽屉和菜单等浮层。

原则：
- 优先使用间距、边界和背景色区分区域。
- 不要将每个表单字段都包裹成独立卡片。
- 不要将所有页面统一设计为卡片宫格。
- 页面结构应由业务信息和操作流程决定。
- 相邻内容区块应有清晰边界，但不能过度分割。

### 4.3 页面滚动

1. 优先保证主体工作区独立滚动。
2. 侧栏和顶部栏保持稳定。
3. 只有长表单、长列表等实际需要时才使用内部滚动容器。
4. 避免页面整体和多个内部容器同时出现难以理解的滚动条。
5. 抽屉内部应有独立、合理的滚动区域。
6. 页面切换时应正确处理滚动位置。
7. 不得通过固定高度隐藏重要内容。

## 五、生产级表格设计

表格是高频工作场景的核心，必须兼顾数据密度、扫描速度和操作准确性。

### 5.1 密度等级

必须支持统一的默认密度；如果现有项目具备密度切换能力，则保留并规范化。

| 规格 | 紧凑模式 | 默认模式 | 宽松模式 |
|---|---:|---:|---:|
| 表头高度 | 36px | 40px | 44px |
| 数据行高度 | 36px | 44px | 52px |
| 字体大小 | 12px | 13px | 14px |
| 单元格水平内边距 | 8px | 12px | 16px |
| 单元格垂直内边距 | 6px | 10px | 14px |

默认使用 44px 数据行高，兼顾生产后台的信息密度和可读性。

如果项目需要展示大量字段和高频记录，可以采用紧凑模式，但必须保证文字和操作目标仍然清晰。

### 5.2 表头

- 使用浅灰白背景。
- 文字左对齐，字重 500。
- 表头文字与正文保持清晰对比。
- 表头不使用明显的渐变。
- 不使用过重的底部边框。
- 排序列必须有明确的排序反馈。
- 支持排序的列应提供适当的交互提示。
- 固定表头时必须处理好滚动区域和列对齐问题。

### 5.3 数据行

默认使用白色背景，行与行之间通过浅色分割线区分。

交互状态：
- 默认：白色。
- 悬停：浅灰蓝背景。
- 选中：低饱和浅蓝背景。
- 禁用：文字和操作入口适度弱化。

规则：
1. 不使用过重的网格线包围每一个单元格。
2. 默认不使用明显的斑马纹。
3. 需要增强扫描效率时，可以采用非常轻微的交替背景。
4. 单行操作按钮不得导致行高变化。
5. 行选中状态必须清晰，但不能覆盖业务状态的语义。
6. 多选操作必须明确显示选中数量及可执行操作。
7. 长文本采用合理的截断、换行或详情查看方式。
8. 不允许因为某一行内容过长而导致整张表格失去稳定的密度。

### 5.4 列宽和对齐

- 编号、日期、状态、数量等字段应按内容设置合理宽度。
- 长文本字段应拥有合理的剩余空间。
- 数字、金额和计量值应根据业务语义统一对齐。
- 操作列保持稳定，不应因数据内容变化而频繁移动。
- 多操作列可使用简洁的操作菜单。
- 固定列必须考虑横向滚动时的遮挡和层级。
- 禁止所有列统一设置为相同宽度。
- 禁止重要字段被挤压到无法识别。

### 5.5 操作列

操作入口优先级：
1. 最常用的一个或两个操作直接展示。
2. 次要操作放入更多菜单。
3. 高风险操作采用明确的危险色和确认机制。

规范：
- 文字操作默认使用主色。
- 删除操作使用危险色。
- 不使用大量独立实心按钮堆叠在同一行。
- 操作列不得无限扩张。
- 图标按钮必须具备提示文本。
- 无权限的操作必须遵循项目既有权限规则。
- 不能只隐藏视觉入口而忽略真实的权限校验。

### 5.6 工具栏与查询区域

表格工具栏可根据业务需要包含：
- 查询条件。
- 搜索按钮。
- 重置按钮。
- 新建或创建入口。
- 批量操作。
- 列配置。
- 刷新。
- 导出。

这些都是可选功能，不得为了套用模板而虚构不存在的操作。

布局规则：
1. 查询条件优先按业务使用频率排列。
2. 常用条件可以放在首行。
3. 次要条件可通过展开区域展示。
4. 查询和重置按钮必须有明确主次关系。
5. 创建或导出等操作应与查询条件保持合理的视觉分组。
6. 查询区不应默认占据过多垂直空间。
7. 表格工具栏与表格之间保持 12–16px 间距。
8. 重置操作必须遵循原有筛选条件的默认值规则。

### 5.7 分页

分页区域应保持稳定，不因数据变化而频繁跳动。

可根据现有项目展示：
- 总记录数。
- 当前页和总页数。
- 每页条数。
- 上一页和下一页。
- 页码跳转。

规范：
- 分页文字使用 12–13px。
- 控件高度与常规表单控件协调。
- 分页区域使用轻量分隔或适当留白。
- 数据刷新后必须遵循原有分页逻辑。
- 筛选条件变化时，按业务需要重置页码。
- 空数据时显示合理的空状态。
- 不得自行修改后端分页参数或响应结构。

## 六、状态标签与业务状态展示

### 6.1 基础样式

- 字体：12px。
- 高度：22px 左右。
- 水平内边距：8px。
- 圆角：4px。
- 使用浅色背景、深色文字和可选的浅色边框。
- 同一业务状态在所有页面中必须保持一致。

状态标签的颜色不能完全取代文字。即使颜色无法区分，用户仍然应该能够识别业务状态。

### 6.2 状态分类

建议使用以下视觉分类：

- 正常、已完成、成功：绿色系。
- 进行中、处理中：蓝色系。
- 待处理、待确认、临近期限：橙色系。
- 异常、失败、已驳回：红色系。
- 未开始、已关闭、未知：灰色系。

这只是视觉映射原则，不是业务状态定义。

执行时必须先读取项目中的枚举、常量、字典和接口数据，建立真实的状态映射表。

禁止：
- 根据中文名称猜测所有状态的含义。
- 将不同业务模块中含义不同的状态强行统一。
- 随意修改后端状态值。
- 在不同页面使用不同颜色表示相同业务状态。
- 用红色展示普通提示。
- 用绿色掩盖尚未完成的任务。

### 6.3 状态与操作的关系

状态标签与操作按钮应当保持语义一致。

例如：
- 已完成的记录不应继续展示普通的执行入口，除非业务明确允许再次执行。
- 已关闭的记录不应默认显示进行中样式。
- 被驳回的记录应保留其真实状态，并根据业务流程展示可用操作。
- 待处理状态可以通过文字强调，但不能单纯依赖高饱和背景。

具体规则以项目业务权限和状态机为准，不得擅自修改流程。

## 七、抽屉与详情面板

抽屉用于查看详情、编辑信息、执行辅助操作等场景，避免用户在简单操作中频繁跳转页面。

### 7.1 抽屉尺寸

推荐宽度：
- 轻量详情：420–480px。
- 常规表单：560–640px。
- 复杂业务表单：720–840px。
- 全屏或接近全屏的复杂任务：仅在确有必要时采用。

尺寸应根据实际字段数量和布局决定，不得强制所有抽屉采用相同宽度。

### 7.2 抽屉结构

统一采用：

1. 固定顶部标题区。
2. 可滚动内容区。
3. 固定底部操作区。

标题区：
- 高度约 56px。
- 左侧显示标题。
- 右侧提供关闭入口。
- 需要时显示辅助说明或状态。
- 底部使用轻量分隔线。

内容区：
- 内边距 20–24px。
- 字段间距 16–20px。
- 复杂表单可以使用分组标题。
- 详情数据应有清晰的标签和值的对应关系。
- 长内容应正确换行或使用适当的截断策略。

底部操作区：
- 高度根据按钮和内边距自适应。
- 默认使用白色背景。
- 顶部设置轻量分隔线。
- 主操作靠右排列。
- 取消等次要操作置于主操作之前。
- 危险操作应单独进行视觉区分。

### 7.3 抽屉行为

1. 打开抽屉后，背景页面应保持稳定。
2. 抽屉内容过长时，仅内容区域滚动。
3. 固定底部按钮不得遮挡最后一个表单字段。
4. 关闭时应遵循项目原有的数据保留规则。
5. 有未保存修改时，应按业务需要提示。
6. 提交过程中应防止重复操作。
7. 校验失败时，应将错误信息清晰呈现。
8. 提交成功后，必须按照原有业务逻辑关闭抽屉或保留当前内容。
9. 打开、关闭和切换记录时，不得产生内容闪动。
10. 抽屉关闭后应恢复合理的键盘焦点和操作上下文。

## 八、抽屉表单规范

### 8.1 表单布局

优先使用单列布局，保证字段标签、控件和校验信息的可读性。

适用双列布局的场景：
- 字段较短。
- 字段之间存在明确的业务关联。
- 抽屉宽度足够。
- 双列不会增加填写难度。

规范：
- 标签与控件之间保持 6–8px。
- 表单项之间保持 16–20px。
- 同一分组内部保持一致的间距。
- 分组之间保持 24–32px。
- 长文本、备注、描述等字段默认占满可用宽度。
- 日期范围、坐标等成组字段应按照实际业务组织。
- 不得为了填满空间而强行采用双列布局。

### 8.2 输入控件

常规控件高度：
- 默认：32px。
- 宽松模式：36px。
- 大尺寸：40px。

规范：
- 输入框、选择器和日期选择器保持统一的基础尺寸。
- 聚焦时使用主色边框。
- 错误时展示清晰的校验信息。
- 禁用状态必须明显。
- 只读状态与禁用状态应有所区别。
- 必填标识必须统一。
- 占位文本不得代替必要的字段标签。
- 下拉选项较多时应提供合理的搜索能力。
- 长文本字段应提供适当的输入区域高度。

### 8.3 表单分组

根据业务实际使用分组标题，例如基本信息、处理信息、关联信息等。

这些名称仅为说明，不应直接生成到所有页面中。

规则：
1. 只有字段具有业务关联时才进行分组。
2. 分组标题使用 14px、600 字重。
3. 分组之间采用间距或轻量分割线。
4. 不要将每组字段都包装成带阴影的独立卡片。
5. 必须保持字段顺序与原有业务流程一致。
6. 不得擅自增加、删除或重命名字段。

### 8.4 校验与提交

- 错误信息应出现在对应字段附近。
- 错误状态使用红色边框和明确的说明。
- 提交过程中禁用重复提交。
- 提交失败时保留用户已填写的信息。
- 提交成功后提供明确反馈。
- 取消操作必须符合原有业务行为。
- 对有副作用的操作提供必要的二次确认。
- 表单校验规则必须与原有业务规则一致。
- 不得为了视觉优化而删除必填校验或改变字段的数据类型。

## 九、按钮与操作反馈

### 9.1 按钮规格

| 类型 | 高度 | 使用场景 |
|---|---:|---|
| 默认 | 32px | 常规操作 |
| 紧凑 | 28px | 表格内轻量操作 |
| 宽松 | 36px | 主要表单操作 |
| 大尺寸 | 40px | 特殊主操作 |

按钮圆角统一为 5px 左右。

按钮类型：
- Primary：主要提交、创建、确认。
- Default：取消、重置、辅助操作。
- Text：详情、查看等轻量入口。
- Danger：删除、撤销等危险操作。
- Disabled：不可执行的操作。

### 9.2 操作层级

每个区域应有明确的主次关系。

规范：
1. 一个主要操作区原则上只有一个主按钮。
2. 次要操作不应使用同样醒目的实心主色按钮。
3. 表格中的操作优先使用文字链接或轻量按钮。
4. 不要在一个区域中堆叠大量不同颜色的按钮。
5. 删除和不可逆操作必须有合理的风险提示。
6. 只有在确实存在业务含义时才展示危险色。
7. 禁用按钮应有明确的不可执行状态。
8. 加载状态必须防止重复提交。

### 9.3 操作反馈

统一处理：
- 成功提示。
- 失败提示。
- 加载状态。
- 空状态。
- 无权限状态。
- 网络异常。
- 表单校验失败。
- 危险操作确认。

反馈样式应与现有项目使用的消息组件保持一致，不得同时引入多套互相冲突的提示系统。

## 十、响应式与窄屏适配

本设计优先适配桌面端生产工作环境，但必须正确处理窗口变化。

规则：
1. 侧栏展开时保证主体内容拥有合理空间。
2. 窄窗口下允许侧栏收起。
3. 表格优先采用合理列宽和横向滚动。
4. 抽屉宽度不得超出可用视口。
5. 双列表单在空间不足时自动变为单列。
6. 按钮组在窄屏下应合理换行或调整布局。
7. 不得通过缩小字体和控件到难以操作的程度来适配屏幕。
8. 不得出现弹窗超出屏幕、操作按钮被遮挡等问题。
9. 移动端如不属于项目支持范围，不需要强行将所有桌面布局改造成移动端设计，但应保证基础可用性。

## 十二、执行步骤

请严格按照以下步骤执行，而不是只给出设计建议。

### 第一步：分析现有项目

识别当前布局、菜单、页面类型、组件库、公共样式和业务交互。

列出需要统一的视觉问题，优先寻找可复用的改造点。

### 第二步：建立全局设计 Token

统一深色侧栏、浅色工作区、字体、间距、圆角、边框、状态色和阴影。

优先修改全局样式与公共主题，避免先逐个页面写死颜色。

### 第三步：统一应用外壳

完善侧栏锚点、菜单选中状态、收起行为、顶部栏和主工作区滚动。

确保不同路由下的导航表现一致。

### 第四步：统一高频组件

优先处理按钮、表格、分页、状态标签、表单、弹窗和抽屉。

确保相同组件在不同业务模块中具有一致的视觉语言。

### 第五步：改造具体页面

根据实际业务结构应用规范。

不强制每个页面使用相同的标题区、查询区、统计卡片或表格布局。

### 第六步：检查交互闭环

验证菜单跳转、查询、重置、分页、排序、表单校验、提交、取消、抽屉开关、权限控制和反馈提示。

### 第七步：验证视觉一致性

检查：
- 侧栏是否固定且状态正确。
- 主体是否具有稳定的留白。
- 表格是否保持合理密度。
- 状态标签是否映射正确。
- 抽屉是否具有固定标题和操作区。
- 控件高度是否统一。
- 圆角和阴影是否克制。
- 长文本和窄屏是否正常。
- 加载、空数据、异常和禁用状态是否完善。

### 第八步：提交改造结果

完成后说明：
1. 修改了哪些文件。
2. 哪些公共组件得到了统一。
3. 哪些页面已经完成改造。
4. 原有业务功能是否保留。
5. 执行了哪些检查或测试。
6. 尚未解决的问题有哪些。

不得声称没有实际执行的测试已经通过。
````
