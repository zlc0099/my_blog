这套提示词面向**百科 / Wiki 条目站**，不是营销官网或作品介绍页。它把「专业、克制、信息密度高、可长时间阅读」作为前提，强调用信息框、表格、内链和目录承载结构化内容，而不是把资料堆成一篇长散文。

它适合游戏、动漫、影视资料站，也适合做个人作品档案、设定集和相关条目网络。具体作品、条目数量、字段和分类由项目实际内容决定，提示词只规定信息结构和阅读体验。

## 它主要解决什么问题

- 资料站容易变成大段文字，缺少清晰的信息层级和可扫描结构。
- 信息框、表格、剧透、版本差异没有统一规范，页面与页面之间不一致。
- 内链只是普通链接，没有未创建条目、悬停预览和条目网络。
- 剧透内容出现在搜索摘要或预览卡片里，破坏阅读体验。
- 深色模式只做简单反色，图片、表格、标签和警示色不可读。
- Agent 输出内容时自由发挥，字段缺失、日期格式、来源和剧透标记不统一。

## 提示词的约束范围

1. **视觉风格**：中性灰白底、按作品类型区分主题色、语义色、正文行高和最大阅读宽度。
2. **三栏布局**：左侧目录、中间正文、右侧信息框；≥1200px 三栏，768–1199px 两栏，<768px 单栏并把信息框移到正文顶部。
3. **标题与目录**：H1/H2/H3/H4 的层级、主题色装饰、锚点、平滑滚动和 scrollspy。
4. **信息框**：封面、原名、字段网格、缺失值、多值折叠、吸顶和外部链接。
5. **表格**：表头、斑马纹、横向分隔线、数字右对齐、日期格式、sticky 表头和排序。
6. **剧透区块**：折叠、警示边框、分级剧透、搜索和预览隔离。
7. **内链与预览**：正文内链、红链、悬停预览卡片和视口自适应。
8. **标签与徽章**：类型、状态、平台、分级和官方认证。
9. **版本对照**：原作/动画/漫画/游戏/真人版 Tab、差异表、URL hash。
10. **深色模式、字体、动效、无障碍**：Token、字体栈、克制的过渡、键盘焦点和表格语义。
11. **Agent 输出约束**：H1、字段两列表、缺失值、剧透 details、内链格式、来源标注和结构化优先。

## 适合什么时候用

- 从零设计游戏 / 动漫 / 影视百科条目站。
- 已有资料站需要统一条目页、信息框、表格和目录规范。
- 需要把「剧透隔离、版本对照、内链网络」作为产品能力，而不是后期补丁。
- 需要 Agent 按固定结构输出条目内容，减少字段和格式漂移。

不适合直接套到电商详情页、营销落地页或没有可靠资料来源的项目。提示词里的 Fandom、Wikipedia、Bangumi、AniList 是气质参考，不是要求复制它们的页面、素材或文案。

## 使用方式

1. 先准备条目模型：字段、类型、版本、角色、制作团队、来源和剧透等级。
2. 把完整提示词、项目技术栈、内容样例和真实数据来源一起交给 Agent。
3. 要求先输出条目页结构和字段规范，再实现三栏布局、信息框和目录。
4. 剧透内容要同时处理折叠、搜索摘要和悬停预览，不能只做一层遮罩。
5. 内链需要 slug 映射和未创建条目状态，不能全部指向空链接。
6. 在桌面、平板和手机宽度下检查目录、信息框、表格横向滚动和 sticky 遮挡。
7. 验收时区分真实数据、缺失值和待核实内容，不虚构官方信息。

## 完整提示词

````prompt
# 百科 Wiki 条目站 UI 与排版 Agent 提示词

## 一、整体视觉风格提示词

【风格定位】
百科 Wiki 网站视觉风格：专业、克制、信息密度高、可长时间阅读。
参考气质：Fandom / Wikipedia 的结构化 + Bangumi / AniList 的二次元审美 + 游戏资料站的沉浸感。

【设计关键词】
结构化 · 卡片化 · 信息框驱动 · 内链网络 · 剧透隔离 · 版本对照 · 深色友好

【色彩原则】
- 主色：中性灰白底（浅色模式 #FAFAFA / 深色模式 #1A1A1E）
- 强调色：按作品类型区分主题色
  · 游戏 → 电光蓝 / 紫 #6C5CE7
  · 动漫 → 樱粉 / 橙 #FF6B81
  · 影视 → 深金 / 藏青 #C9A227
- 语义色：剧透警示 #E17055、待核实 #FDCB6E、官方认证 #00B894
- 文本：正文 #2D3436，次要 #636E72，链接 #0984E3，已访问 #6C5CE7

【排版基调】
- 正文行高 1.7，段间距 1em，最大阅读宽度 72ch
- 标题层级清晰，H2 带下边框分隔，H3 前缀符号（如 ▸）
- 数据用等宽字体（销量、评分、日期对齐）
- 大量使用表格、信息框、标签、折叠块承载结构化信息

## 二、页面版式（Layout）提示词

【条目页整体布局】
桌面端三栏结构：

┌──────────────────────────────────────────────┐
│ 顶部导航栏（Logo / 搜索 / 分类 / 语言切换）      │
├──────────┬───────────────────────┬───────────┤
│ 左侧目录  │   主内容区              │ 右侧信息框  │
│ (TOC)    │   概述/剧情/角色/制作…   │ (Infobox) │
│ 吸顶跟随  │   最大宽 72ch           │ 吸顶跟随    │
├──────────┴───────────────────────┴───────────┤
│ 底部：相关条目 / 参考资料 / 编辑入口             │
└──────────────────────────────────────────────┘

【响应式规则】
- ≥1200px：三栏（目录 + 正文 + 信息框）
- 768–1199px：两栏（正文 + 信息框），目录折叠为悬浮按钮
- <768px：单栏，信息框折叠到正文顶部，目录为抽屉式

【区块顺序】
概述 → 信息框（移动端）→ 剧情简介 → 剧透区块（折叠）→ 角色 → 制作团队 → 音乐 → 发行信息 → 评价反响 → 衍生作品 → 相关条目 → 参考资料

## 三、标题层级样式提示词

【标题规范】
H1（条目标题）：2rem / 粗体 / 底部 2px 主题色下划线 / 右侧附原名小字（灰色 0.9rem）
H2（一级章节）：1.5rem / 粗体 / 左侧 4px 主题色竖条 / 上间距 2em 下间距 0.8em / 底部细分割线
H3（二级章节）：1.2rem / 半粗 / 前缀符号 "▸" / 颜色略深
H4（小节）：1rem / 粗体 / 全大写或小标题样式，无装饰

【锚点与目录联动】
- 所有 H2/H3 右侧悬停显示锚点链接图标 "¶"
- 点击锚点平滑滚动并高亮目标区块 1.5s
- 左侧 TOC 随滚动高亮当前章节（scrollspy）

## 四、信息框（Infobox）样式提示词

【信息框视觉】
- 卡片样式：浅色背景 #F5F6FA / 圆角 8px / 1px 边框 #DFE6E9 / 轻阴影
- 顶部：作品主视觉图（16:9 或 3:4 封面），圆角上沿
- 图片下方：作品中文名（居中粗体）+ 原名（小字灰色）
- 字段区：两列网格 —— 字段名（左，灰色 0.85rem）| 值（右，深色）
- 字段行分隔：1px 浅虚线，最后一行无
- 缺失字段值显示 "—"，字段名保持对齐
- 类型标识：顶部右上角彩色标签（游戏 / 动漫 / 影视，用主题色）

【交互】
- 信息框吸顶（sticky），滚动时保持可见
- 多值字段（如多平台）换行展示或折叠为 "+3"
- 外部链接字段（官网）附 ↗ 图标

## 五、表格样式提示词

【表格规范】
- 表头：主题色浅底（如 #EEF1FF）+ 粗体 + 左对齐
- 斑马纹：偶数行 #FAFBFC
- 边框：仅横线（1px #ECEFF1），无竖线，极简
- 单元格内边距：10px 14px
- 数字列（销量 / 评分 / 集数）：右对齐 + 等宽字体
- 日期列：统一 YYYY-MM-DD，等宽字体
- 长表格：表头 sticky，超出高度可滚动
- 排序：表头点击排序，排序箭头用 ▲▼

【角色表格专用】
列：角色名（含头像缩略图 32px 圆形）| 声优 / 演员 | 定位（主要 / 次要标签）| 简介
定位用彩色小标签：主要 = 主题色，次要 = 灰色

## 六、剧透区块样式提示词

【剧透区块视觉】
- 默认折叠，外框为警示色虚线边框（#E17055）
- 折叠头：⚠️ 图标 + "以下内容包含重大剧透，点击展开" + 右侧 ▾
- 展开头背景：淡警示色 #FFF3EF
- 展开后内容区左侧 3px 警示色竖条
- 折叠实现：`<details>` / `<summary>` 或 JS 折叠组件
- 剧透内文本不参与搜索摘要、不在预览卡片中显示

【分级剧透】
轻度剧透：黄色边框 #FDCB6E，提示 "含轻微剧透"
重大剧透：橙色边框 #E17055，提示 "含重大剧透"

## 七、内链与卡片提示词

【内链样式】
- 正文内链：主题色文字 + 无下划线，hover 显示下划线
- 内链格式 [[条目名]]，渲染为可点击胶囊或无下划线链接
- 未创建条目：红色虚线下划线 + "?" 尾标（红链）

【悬停预览卡片】
- hover 300ms 后弹出预览卡：条目缩略图 + 标题 + 一句话摘要 + "查看条目 →"
- 卡片：白底 / 圆角 10px / 阴影 / 最大宽 320px
- 位置自适应（避免超出视口）

## 八、标签与徽章提示词

【标签样式】
- 圆角胶囊（radius 999px），小字 0.75rem，内边距 2px 8px
- 类型标签：游戏 / 动漫 / 影视，用各自主题色浅底深字
- 状态标签：连载中（绿）、已完结（灰）、待核实（黄）、官方认证（绿勾）
- 平台标签：Steam / PS / Switch 等，中性灰底
- 分级标签：如 CERO / PEGI / 年龄分级，用警示色系

【徽章】
- 官方认证徽章：绿色勾 + tooltip "官方确认"
- 精选条目：金色星标

## 九、版本对照（Tab）提示词

【多版本切换】
- 顶部 Tab 栏：原作 / 动画 / 漫画 / 游戏 / 真人版
- 选中 Tab：主题色下划线 + 深色文字；未选中：灰色
- Tab 内容切换带淡入动画（150ms）
- 差异对照表：列 = 各版本，行 = 设定项，冲突单元格加浅色背景标记
- Tab 状态写入 URL hash，便于分享定位

## 十、深色模式提示词

【深色模式规范】
- 背景 #1A1A1E，卡片 #24242A，边框 #33333C
- 正文 #E4E6EB，次要 #A0A4AD，链接 #74B9FF
- 主题色降低饱和度 10%，避免刺眼
- 图片加轻微暗化遮罩（opacity 0.9）
- 剧透警示色保持可辨识（#FF7675）
- 切换按钮位于导航栏右侧，跟随系统或手动切换，localStorage 记忆

## 十一、字体与排版细节提示词

【字体栈】
- 正文：系统字体栈（-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif）
- 标题：同上，字重 600–700
- 数据 / 代码：等宽（"JetBrains Mono", "SF Mono", Consolas, monospace）
- 日文原名：优先日文字体（"Noto Sans JP", "Hiragino Sans"）

【排版细节】
- 正文最大宽 72ch，居中偏左
- 段落间距 1em，行高 1.7
- 引用块：左侧 4px 灰条 + 斜体 + 灰色文字
- 列表：无序用 ·，有序用数字，层级缩进 1.5em
- 分隔线：1px #ECEFF1，上下留白 2em
- 首段（概述）字号略大 1.05rem，行高 1.8

## 十二、动效与微交互提示词

【动效原则】克制、快速、服务阅读
- 折叠 / 展开：height 过渡 200ms ease
- Tab 切换：淡入 150ms
- 内链 hover：下划线滑入 120ms
- 锚点跳转：smooth scroll 300ms + 目标高亮脉冲 1.5s
- 加载骨架屏：信息框与表格优先占位
- 减少动效：尊重 prefers-reduced-motion，关闭非必要动画

## 十三、可访问性提示词

【无障碍规范】
- 对比度 ≥ 4.5:1（正文），≥ 3:1（大字 / 图形）
- 所有交互元素可键盘聚焦，focus 有可见轮廓（2px 主题色）
- 图片 alt：作品名 + 描述（如 "《作品名》官方主视觉图"）
- 表格使用 `<th scope>` 标注表头
- 剧透折叠用原生 details 或 ARIA 展开状态
- 色彩不作为唯一信息载体（标签同时用文字 / 图标）

## 十四、给 Agent 的输出约束（可直接嵌入系统提示）

生成百科条目时，按以下排版约定输出内容：

1. 条目标题用 H1，附原名小字。
2. 每个 H2 章节前不加多余空行，章节间用分隔线。
3. 信息字段一律用两列表格（字段名 | 值），缺失填 "—"。
4. 多值用「、」分隔；日期 YYYY-MM-DD；数字右对齐。
5. 剧透内容必须包裹在 `<details><summary>⚠️ 含剧透，点击展开</summary>…</details>`。
6. 内链用 [[条目名]]，未确定条目加 [[条目名?]]。
7. 数据类信息标注来源与时间，如 "（MC 92，2025-06）"。
8. 文末附 "相关条目" 3–5 个内链 + "参考资料" 来源类型列表。
9. 表格优先于长段落罗列；能结构化就不写成散文。
10. 全部输出兼容深色模式（不硬编码白底黑字）。
````
