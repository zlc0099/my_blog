## 背景

不同 Agent 之间重复解释同一套规范的成本很高：UI 怎么做、任务怎么拆、交付前怎么验收。与其每次复制长提示词，不如把流程写成标准 Markdown，让支持 SKILL.md 的工具直接读取。

## 组成

目前包含三个技能：

| 技能 | 解决的问题 | 调用方式 |
| --- | --- | --- |
| `frontend-ui-design` | 统一 Design Token、布局、组件、动效与可访问性 | 显式调用 |
| `fullstack-dev-workflow` | 需求澄清、原子任务清单、TDD、证据化验收 | 自动触发 |
| `web-test-pro` | 页面体检、多视口截图、失败请求与可访问性检查 | 显式调用 |

每个技能只依赖 Markdown、相对路径引用和标准 CSS/脚本，不绑定特定平台。Claude Code、Cursor、Codex、Qoder 等能读取 SKILL.md 的工具都可以直接使用。

## 设计原则

1. **触发条件写清楚**：说明什么时候加载、什么时候不加载，避免技能在不相关任务里频繁出现。
2. **每一步都有产物**：澄清输出问题清单，设计输出契约，实现输出可运行代码，验收输出命令结果。
3. **边界优先**：明确不做什么，比列出更多能力更能控制范围。
4. **失败可回退**：信息不足、验证失败或缺少依赖时，先报告，不擅自扩大改动。
5. **跨 Agent 兼容**：不依赖某个平台的专有工具或 API。

## 关键问题

### 规范太长会被忽略

第一版把每个细节都写了进去，结果实际执行时只读了开头。后来把核心铁律放在最前面，把具体参考文档拆成按需加载，执行率明显提高。

### 自动触发误伤

全栈工作流最初对所有开发任务生效，包括只改一行样式的情况。后来在 description 中补充了正反例和适用范围，并增加了“轻量任务可跳过完整流程”的说明。

### 验证不能靠口头完成

测试技能要求输出真实命令结果和报告，不允许用“应该没问题”代替。这一步让很多隐性问题在交付前暴露，例如移动端横向滚动和失败的静态资源请求。

## 后续

- 把常用的提示词模板直接纳入技能目录。
- 增加一个统一的检查入口，减少多个脚本之间的切换。
- 为每个技能补充真实案例，而不是只有规则说明。
